# 영토 (지역 점령, 별도 컨텐츠)

> 상태: 기획 중 (구현 전, **서버 도입 후**)
> 관련: [main-screen.md](main-screen.md)(영토 탭), [story.md](story.md), [pvp.md](pvp.md), [hiring.md](hiring.md), [battle.md](battle.md) 5장(전투 입구·출구), [structure.md](../structure.md)

---

## 1. 목적 (확정, 2026-11-09)

- 스토리와 **별도 컨텐츠**로 만든다. 스토리는 혼자 하는 컨텐츠·튜토리얼로 남는다.
- 실제 지역(행정구역)을 땅으로 삼는 **땅따먹기**다. 내가 있는 곳(GPS)과 관련된 지역을 차지하고 지킨다.
- 지역이 클수록 혼자서는 못 차지하고 **연합(길드)**이 필요하다.

---

## 2. 지역 단계

행정구역 계층: **시·도 → 시·군·구 → 읍·면·동 → 리**.

- 읍·면·동은 **같은 단계**다. 리는 읍·면 아래에만 있고, 도시의 동 아래에는 리가 없다.
- 읍은 보통 면보다 크다 (인구 2만 이상의 도시형).

| 단계 | 예 | 필요한 규모 (처음 제안) | 비고 |
|---|---|---|---|
| 리 | ○○리 | 군단 1개 (혼자) | 도시의 동은 이 단계가 없으므로 아래 "동 나누기" 참고 |
| 읍·면·동 | ○○면, ○○읍, ○○동 | 연합: 군단 5개 | 사용자 제안은 "읍 5, 면 10"이었으나 읍이 면보다 큰 경우가 많아 같은 단계로 묶음 (미결 1) |
| 시·군·구 | ○○군, ○○구 | 연합: 군단 10개 이상 | |
| 시·도 | ○○도 | 연합 여러 개 (대규모 행사) | 시즌 행사로만 (제안) |

- **필요한 규모는 데이터**로 정한다 (단계별 기본값 + 지역별 덮어쓰기). 인구·면적이 아주 다른 지역은 지역별 값으로 맞춘다.
- 동 나누기 (제안): 도시의 동은 리가 없어 혼자 차지할 땅이 없다. 동을 격자(예: 1km)로 나눈 "구역"을 리 단계로 쓴다.

## 3. 위치 (GPS) 판정

| 항목 | 내용 |
|---|---|
| 좌표 → 지역 | 서버가 판정한다 (행정구역 경계 데이터: 통계청·국토부 공개 자료, 또는 지도 API의 좌표→주소). 시·도~읍·면·동은 확실, 리는 법정리 경계 자료로 (정확도 확인 필요) |
| 어디를 공격할 수 있나 | **지금 있는 지역과 이웃 지역** (제안). 먼 지역은 연합원이 있는 곳을 통해서만 |
| 위치 확인 시점 | 영토 탭을 열 때와 공격을 신청할 때만 (계속 추적하지 않는다) |
| 조작 방지 | 서버 검증: 이동 속도 이상(순간 이동), 가짜 위치 앱 감지, 같은 기기 여러 계정. 의심되면 영토 기능만 제한 |
| 기기 | 위치 서비스는 외부 서비스 인터페이스 뒤에 둔다 (`ILocationService`: 끔 / 가짜(개발용 고정 좌표) / 실제). 꺼도 게임은 동작한다 (영토 탭만 잠김) |

## 4. 법·안전·사생활 (출시 전 필수)

- **위치정보법**: 위치기반서비스를 하려면 **위치기반서비스사업 신고**(방송통신위원회)가 필요하다. 위치정보 이용약관, 이용 동의, 수집·이용·보관 기록 의무가 있다. 출시 전에 법률 검토.
- 다른 유저의 **정확한 위치는 절대 보여주지 않는다**. "어느 지역 소속"만 보인다.
- 위치 기록은 판정에 필요한 만큼만, 짧게 보관한다.
- 이동 중(차량 속도) 플레이는 막는다. 위험한 곳(도로·철로)에 가야 하는 구조를 만들지 않는다 — 공격은 "이웃 지역"까지 원격으로 가능하므로 직접 가지 않아도 된다.
- 미성년자 보호(보호자 동의 등)는 약관 단계에서 함께 정한다 ([startup.md](startup.md)).

## 5. 전투와의 연결

- 전투 모듈은 그대로 쓴다. 영토 전투도 **`BattleSetup`을 만들어 넘기고 `BattleResult`를 받는다** (battle.md 5장). 스토리의 스텝 대신 **지역 데이터**(지형 템플릿·수비군·조건)에서 만든다.
- 수비 쪽:
  - 지역 주인(유저·연합)이 등록한 **수비 편성**을 AI가 지휘한다 (pvp.md의 비동기 대전과 같은 방식, [ai.md](ai.md)).
  - 주인이 없는 지역은 **AI 수비군**(지역 단계별 난이도). 유저가 적은 시골도 비어 있지 않게 한다.
- 결과 확정은 **서버의 전투 재현**으로 한다 (명령 기록 + 시드, R-29). 기기 결과는 믿지 않는다.
- 연합 전투: 연합원 여러 명의 군단이 한 전투에 참가 (N:N 대전 구조, [pvp.md](pvp.md)). 실시간이 어려우면 "참가 신청 → 예약 시각에 동시 위임 전투"로 시작 (제안).

| 보상 | 차지한 지역에서 시간당 자원(군량·돈) — 연합원에게 나눔. 수치는 [economy.md](economy.md)와 함께 |
| 고용 | 부족한 군단은 고용으로 채울 수 있다 ([hiring.md](hiring.md)) |

## 8. 개발 순서 (제안)

1. 서버 기본 (계정·저장, [hiring.md](hiring.md)와 같은 기반)
2. 위치 서비스 인터페이스 + 가짜 구현, 지역 데이터 형식 (경계는 개발용 몇 곳만)
3. 영토 전투 = 지역 데이터 → `BattleSetup` (AI 수비군만, 혼자 리 단계)
4. 연합, 수비 편성 등록, 서버 재현 확정
5. 실제 경계 데이터·조작 방지·법적 절차 → 출시
