## 1. 전투 구조

```
전투 (예: "○○ 전투", "아군 세력 대 적 세력")
 ├─ 팀 1 (아군): 대장 + 군단 N개
 └─ 팀 2 (적군): 대장 + 군단 N개
   (유저 대전 확장 시: 팀 N개, 팀마다 유저 여러 명 — pvp.md)
      └─ 군단 = 장수 1명 + 총병력 + 예비 병력 + 사기 + 진형
           └─ 소부대 6개: 선봉 / 중앙(장수) / 좌익 / 우익 / 좌비 / 우비
                각각 병종(보병·기병·궁병)과 화면 병사 수를 가짐
```

- 플레이어는 직접 싸우지 않고 **군단 선택 → 진형 → 명령**으로 지휘한다.
- 화면에서는 "선택한 아군 군단 vs 선택한 적 군단"의 대치 상황을 보여준다.
- 군단마다 **소유자**와 **지휘 주체**(이 기기 플레이어 / AI / 위임, 확장 시 원격 플레이어)를 가진다. 유저 대전 확장 대비 ([pvp.md](pvp.md)).

## 2. 핵심 시스템

### 2.0 군단 수 (가변)
- 한쪽당 군단 수는 **고정이 아니라 가변**이다.
  - 스텝이 올라갈수록 늘어나게 할 수 있다.
  - 맵에 따라 많게도, 적게도 둘 수 있다.
- **기본값 3개** (`balance.json`의 `defaultMaxCorps`).
- 결정 순서: **스텝 JSON 값 → 맵 데이터 값 → 기본값(3)** 중 먼저 있는 값을 쓴다.
- 맵의 출현 지점 수보다 많을 수는 없다. 맵 데이터에 지점을 넉넉히 두거나, 지점 하나에 여러 군단을 배치한다.
- 아군과 적군을 따로 정할 수 있다 (`maxCorps.player`, `maxCorps.enemy`).
- 아군 출전 군단은 **부대 편성 탭**에서 정한 편성을 쓴다. 스텝 JSON은 출전 가능한 군단 수와 출현 지점만 정한다.

### 2.1 명령 (군단 단위)

플레이어 명령은 군단 전체의 **의도**만 정한다. 실제로 누구와 어떻게 싸울지는 각 소부대가 자기 능력치에 따라 스스로 판단한다 (2.2.2 참고).

| 명령 | 군단 의도 | 소부대 판단에 주는 영향 (초안) |
|---|---|---|
| 돌격 | 적진으로 빠르게 전진 | 공격성 크게 상승, 인지 반경 확대, 진형 이탈 허용 |
| 공격 | 지정한 적 군단(없으면 가장 가까운 적)과 교전 | 기본 공격성 |
| 대형 | 진형을 유지하며 전진·정비 | 진형 위치 복귀 우선, 반경 안의 적만 처리 |
| 성벽 | (성새전 전용) 성벽 위 배치·공격 / 성문 공격 | 성새전 규칙에서 정의 |
| 수비 | 제자리 유지, 방어 상승 | 진형 위치에서 멀리 나가지 않음 (추격 거리 축소) |
| 후퇴 | 전장 이탈, 병력 보존 | 교전보다 이탈 우선 |
| 위임 | AI가 군단 명령까지 대신 내림 (토글) | - |

### 2.2 진형
- 진형은 **6개 소부대의 배치 위치**다. 군단이 이동하면 각 소부대는 진형이 정한 자기 자리로 이동한다.
- 전투 중 진형을 바꾸면 소부대들이 새 위치로 이동한다.
- 진형마다 **장단점(특성치)**과 **진형 상성**을 정의한다. 배치에서 나오는 자연스러운 효과(기병 선봉이 먼저 부딪힘 등)에 더해, **능력치가 같으면 진형 상성으로 승패가 갈리도록** 보장한다.
- 진형 종류는 JSON(`formations.json`)으로 정의한다. 첫 버전은 아래 6종.

### 2.2.1 진형 종류 (첫 버전 6종, 초안)

| 진형 | 형태 | 장점 | 단점 | 어울리는 장수 |
|---|---|---|---|---|
| 어린(魚鱗) | 중앙 밀집 | 중앙 돌파력 | 측면이 약함 | 균형형 |
| 학익(鶴翼) | 양 날개를 펼침 | 포위, 측면 공격 | 중앙이 얇음 | 통솔형 |
| 봉시(鋒矢) | 화살촉 | 돌격 속도, 돌파 | 측면·후방 매우 취약, 방어 낮음 | 맹장 |
| 방원(方圓) | 원형 | 사방 방어, 포위 무력화, 사기 안정 | 공격력·이동 속도 낮음 | 책사 |
| 안행(雁行) | 사선 배치 | 측면 우회, 궁병 화력 | 정면 압박에 약함 | 지력형 |
| 언월(偃月) | 장수가 앞에 선 초승달 | 장수 용맹 효과 극대화 | 장수가 노출됨 (일기토·피격 위험) | 맹장 |

진형 특성치 (진형마다 JSON 값으로 정의):

| 특성치 | 의미 |
|---|---|
| 정면 폭 | 동시에 교전하는 병사 수 |
| 돌파력 | 정면 공격 배율 |
| 측면 방어 | 측면·배후 피격 시 피해 감소 |
| 이동 속도 | 군단 이동 배율 |
| 응집력 | 교전 중 대형이 흐트러지는 정도 |
| 전환 시간 | 다른 진형으로 바꾸는 데 걸리는 시간 (전환 중에는 취약) |

진형 상성표 (행이 공격 측. ○ 유리, × 불리, - 보통). 각 진형은 유리 2, 불리 2, 보통 1:

| 공격＼상대 | 어린 | 학익 | 봉시 | 방원 | 안행 | 언월 |
|---|---|---|---|---|---|---|
| 어린 |  | ○ | - | × | × | ○ |
| 학익 | × |  | ○ | × | ○ | - |
| 봉시 | - | × |  | ○ | × | ○ |
| 방원 | ○ | ○ | × |  | - | × |
| 안행 | ○ | × | ○ | - |  | × |
| 언월 | × | - | × | ○ | ○ |  |

- 근거: 어린은 학익의 얇은 중앙을 뚫고, 방원은 학익의 포위를 무력화하며, 봉시는 방원 한 점을 집중 돌파하고, 학익은 봉시의 약한 측면을 감싼다 (나머지도 같은 방식).
- 상성 보정값(예: 유리 +25%p, 불리 −25%p)은 `balance.json` 값. 가산 방식으로 다른 보정과 더해진다 (2.4.2).
- **검증 방법:** 같은 능력치·병력으로 모든 진형 조합을 자동 시뮬레이션해서, 상성표대로 승패가 나오는지 테스트한다 (밸런스 회귀 테스트).

### 2.2.2 소부대 자율 판단 (능력치 기반)

소부대마다 **능력치를 입력**하고, 능력치가 높을수록 더 넓고 똑똑하게 판단한다.

| 판단 수준 | 행동 |
|---|---|
| 기본 | 진형 위치를 지키다가 **인지 반경 안의 가장 가까운 적**을 처리하고 다시 진형 위치로 돌아온다 |
| 중간 | 반경 안의 적 중 **유리한 상대**(병종 상성, 약해진 적)를 골라 처리한다 |
| 높음 | 전장을 보고 **빈 곳을 스스로 메운다** (밀리는 아군 지원, 비어 있는 측면 방어, 적 측면·배후 공략) |

- 판단 수준은 단계별로 고정하지 않고 **능력치 값으로 연속적으로** 반영한다. 행동마다 점수를 매기고 가장 높은 행동을 고르는 방식이며, 능력치가 높을수록 상위 행동이 선택될 기회가 커진다.
- 능력치 범위는 **1~100, 소수점 허용** (예: 72.5). 능력치 항목은 **고정 목록이 아니라 데이터(`stats.json`)로 정의**한다 (2.9 참고). 코드에서는 실수(float)로 처리하고 화면에는 정수로 표시한다. 나중에 세분화가 필요하면 소수점 값을 그대로 쓰면 된다.
- 소부대 능력치 (초안):

| 능력치 | 의미 |
|---|---|
| 공격 / 방어 | 교전 능력 |
| 속도 | 이동 속도 |
| 시야 | 볼 수 있는 거리 (전장 안개를 걷어냄, 2.10 참고) |
| 공격 거리 | 공격이 닿는 거리. 모든 병종 (보병 1, 창병 2, 궁병 10 등, 2.16) |
| 진형 변경 속도 | 진형을 바꾸는 데 걸리는 시간 (병종·훈련도, 장수 규율 보정) |
| 탐지 | 숨은 적(복병 등)을 찾아내는 능력 |
| 인지 반경 | 보이는 적 중에서 반응하는 거리 (시야보다 작음) |
| 판단력 | 상위 행동(유리한 상대 선택, 빈 곳 메우기)을 고르는 능력 |
| 추격 거리 | 진형 위치에서 벗어나 쫓아갈 수 있는 최대 거리 |

- 군단 명령은 이 능력치에 보정을 건다 (예: 돌격은 인지 반경·추격 거리 증가, 수비는 추격 거리 감소).
- 장수 능력치가 소부대 판단과 반응에 보너스를 준다 (2.6 참고).
- 새 행동은 클래스를 추가하는 것만으로 붙일 수 있게 한다 ([../structure.md](../structure.md) 3.3 참고).

### 2.3 병종과 성장

**병종 뼈대: 2개의 축** (제안)

| 축 | 병종 | 역할 |
|---|---|---|
| **상성 삼각형** | 창병 · 궁병 · 기병 | 서로 물고 물림: 창병 > 기병 > 궁병 > 창병 |
| **기준 병종** | 보병 | 상성 없이 균형. 전선 유지(높은 방어), 점령·공성 진입 |
| 역할 병종 (보조) | 첨병(척후병), 투석기 | 상성 밖에서 정보·공성 역할 |
| 지형 병종 (확장) | 산악병, 수군 등 | 특정 지형에서만 강함 |

- 모든 특화 병종(등갑병, 노병, 철기 …)은 위 뼈대 중 하나에서 갈라져 나온다.
- 기병이 빠지면 창병의 존재 이유와 측면·배후 기습(빠른 부대)이 사라지므로, 뼈대에 기병은 필수다.

**기본 4병종** (병종별 능력치·이동 가능 지역은 2.16)

| 병종 | 성격 | 강함 | 약함 |
|---|---|---|---|
| 보병 | 균형형, 방어 높음, 전선 유지 | - | - |
| 창병 | 대기병 | 기병 | 궁병 |
| 궁병 | 원거리 | 창병 | 기병 |
| 기병(기마병) | 빠름, 돌격 | 궁병 | 창병 |

**성장 특화 (승급 트리)**

전체 병종 트리, 태그, 강점·약점, 상성 요약, 개발 순서는 **[troops.md](troops.md)**에 정리했다. 요약:

```
보병 ─┬─ 방패병 ─┬─ 근위병          창병 ─┬─ 장창병 ─── 창벽병
      │          └─ 등갑병                ├─ 극병 ───── 정예극병
      ├─ 도부수 ─── 돌격보병              └─ 투창병
      └─ 경보병 ─── 산악병
궁병 ─┬─ 노병 ─┬─ 연노병           기병 ─┬─ 경기병 ─── 유격기병
      │        └─ 강노병                  ├─ 중기병 ─── 철기
      ├─ 장궁병                           └─ 궁기병
      └─ 화궁병
첨병 ─┬─ 정찰기병                  공성: 투석기, 충차, 운제, 노포, 공병, 대투석기
      └─ 매복병                    확장: 수군, 지원(고수·의무병), 테마 특수
```

- 승급은 **사이드그레이드**: 강점을 얻는 만큼 약점도 생긴다 (영원한 승자 없음).

- 병종은 `troopTypes.json`에 **단계(tier), 상위 병종, 승급 조건**과 함께 정의한다. 새 병종은 JSON만 추가한다.
- 상성은 병종 이름이 아니라 **태그**(`melee`, `ranged`, `mounted`, `polearm` … [troops.md](troops.md) 2장)로 계산한다. 그래서 새 특화 병종도 태그만 달면 상성표에 자동으로 들어간다.
- 승급 조건(초안): 소부대 숙련도(경험), 장수 레벨, 스텝 진행에 따른 해금.
- 공격 방향에 따른 피해 배율: 정면 / 측면 / 배후.

### 2.4 병력과 화면 병사 (비율 표현)

- 전투는 **병력 숫자**로 계산하고, 화면 병사 1명이 **병력 N명**을 대표한다 (예: 1명 = 병력 50명).
- **비율 N은 기기 성능에 맞춰 정한다.** 끊기지 않는 선에서 최대한 많은 병사를 보여주는 것이 목표다.
  - 기기별 **화면 병사 예산**(한 화면 최대 병사 수)을 정하고, 전투 시작 시 `N = 전장 전체 병력 ÷ 예산`으로 계산한다.
  - 품질 단계(저·중·고)와 **자동 조정**을 둔다. 자동이면 첫 몇 초의 프레임을 보고 예산을 올리거나 내린다.
  - 한 전투 안에서는 모든 군단이 **같은 비율**을 쓴다. 그래야 화면 크기가 실제 병력 차이를 그대로 보여준다.
- 병력이 줄어든 만큼 병사가 쓰러진다. 병력 N명 분량의 손실이 쌓일 때마다 1명이 쓰러진다.
- 먼 거리의 병사는 단순한 모델로 그려서(LOD) 더 많은 병사를 보여준다.

### 2.4.1 전열과 후열 (전선 유지)

- 진형의 **정면 폭**만큼만 앞줄에서 교전하고, 나머지는 뒤에 대기한다.
- 앞줄이 쓰러지면 **뒷줄이 앞으로 나와 빈자리를 채운다.** 원작의 "화면 밖에서 걸어 나와 보충"을 화면 안 후열 이동으로 표현한다.
- 앞줄이 한꺼번에 무너지면 후열이 정렬하기 전에 각개격파당한다. 그래서 전선 유지(보병·창병이 버티고 궁병이 뒤에서 공격)가 중요하다.

### 2.4.2 피해 계산 (가산 방식)

- 기본은 **병력 1:1 교환**이다. 같은 조건이면 같은 병력이 서로 같은 피해를 준다.
- 상성과 상황은 **배율을 곱하지 않고 퍼센트 포인트로 더한다.**

```
최종 피해 = 기본 피해 × (100% + 보정 합계)
보정 합계 = 병종 상성 + 진형 상성 + 방향(측면·배후) + 지형 + 사기 + 장수(용맹 등) + 스킬 …
```

- 예: 병종 유리 +20, 측면 공격 +15, 상대가 숲에 있음 −10 → 합계 +25 → 피해 ×1.25.
- 보정 합계에는 상·하한을 둔다 (예: −60 ~ +100, 설정값). 유리한 조건이 아무리 겹쳐도 수치가 폭주하지 않는다.
- 같은 능력치라면 진형 상성 보정이 승패를 가른다 (2.2.1).
- 모든 보정값은 `balance.json`에 있고, 스텝별로 덮어쓸 수 있다.

### 2.4.3 수치 조정 방법

- **코드 수정 없이 조정**: 모든 수치는 JSON 값이다.
- **실시간 조정 패널**(개발용 빌드 전용): 전투 중에 보정값을 바꿔 보면서 바로 확인한다.
- **자동 시뮬레이션**: 화면 없이 전투 규칙만 돌리는 시뮬레이터로 같은 조건을 수백~수천 판 실행해 승률과 평균 손실을 표로 뽑는다. Claude도 이 시뮬레이터로 수치를 테스트하고 조정안을 낼 수 있다.
- 진형 상성 36개 조합 테스트는 수치를 바꿀 때마다 자동으로 돌려서, 상성이 깨지면 바로 알 수 있게 한다.

### 2.4.4 군단 병력 한도와 전투 손실

**군단 병력 한도 (장수 통솔에 따라)**
- 군단이 거느릴 수 있는 최대 병력은 **장수의 통솔**로 정한다.
- **최저 5,000 ~ 최대 20,000.** 통솔 1이면 5,000, 통솔 100이면 20,000 (그 사이는 비례, 공식은 설정값).
  - 예: 통솔 50 → 약 12,400.
- 새 게임 초기 지급 군단은 이 한도만큼 병력을 채워서 지급한다.
- 징병·모병으로도 한도를 넘을 수 없다.

**전투 손실: 사망과 부상**
- 전투에서 줄어든 병력은 **사망**과 **부상**으로 나뉜다 (비율은 설정값).
- **사망: 회복 불가.** 영구히 사라진다.
- **부상: 시간이 지나면 회복**한다 (회복 속도는 설정값, 실제 시간 기준, `ITimeProvider` 사용).
  - 부상병은 회복될 때까지 출전 병력에 포함되지 않는다.
- 줄어든 병력을 채우는 방법 ([economy.md](economy.md)):

| 방법 | 대상 | 비용 |
|---|---|---|
| 자연 회복 | 부상병 | 없음 (시간) |
| 징병 | 새 병사 (사망 손실 보충) | **군량** |
| 모병 | 새 병사 (사망 손실 보충) | **돈** (군량 소모 없음) |
| 치료 (즉시 회복) | 부상병 | 징병 또는 모병 비용의 **절반** (군량 또는 돈, 플레이어 선택) |

- 장수 자신은 전투에서 죽지 않는다 (퇴각·포로, 2.5.1).

### 2.5 사기

- **시작 사기는 장수 역량으로 정한다** (확정). 역량이 높은 장수의 군단은 높은 사기로 시작하고, 전투 중 사기 회복도 빠르다.
- 사기(0~100)는 **피해 계산의 가산 항목**이다 (2.4.2). 기준값(예: 50)보다 높으면 +, 낮으면 −.
- **사기 보정은 공격과 방어로 나뉜다** (확정):
  - 사기가 높을 때 **공격 가산**은 장수 **무력**에 비례해 커진다.
  - 사기가 높을 때 **방어 가산**은 장수 **지력(지략)**에 비례해 커진다.
  - 예: 사기 100 + 무력 80 → 공격 +20%p, 사기 100 + 지략 40 → 방어 +10%p (설정값).
  - 사기가 기준보다 낮으면 공격·방어 모두 감산 (예: 사기 0 → −30%p).
- 사기 증감 요인:

| 하락 | 상승 |
|---|---|
| 병력 손실 | 적 소부대 격파 |
| 측면·배후 기습 당함 | 장수 용맹 (무력) |
| 문관(무력 낮은 장수) 피격 | 사기 스킬 |
| 일기토 패배 | 일기토 승리 |
| 근처 아군 군단의 퇴각·장수 포로 | 수비 명령 중 서서히 회복 |

- 수치는 모두 `balance.json` 값.

### 2.5.1 퇴각과 포로

전투에서 군단이 빠지는 경우는 두 가지다.

**① 퇴각 (장수가 도망을 선택)**
- 적 AI는 사기·병력이 기준 이하로 떨어지면 장수 **성향**에 따라 퇴각을 선택한다 (신중한 장수는 일찍, 용맹한 장수는 늦게).
- 플레이어는 "후퇴" 명령으로 직접 퇴각할 수 있다. 위임 상태면 AI가 같은 기준으로 판단한다.
- 퇴각하는 군단은 전장 가장자리(또는 본진 방향)로 이동하고, 빠져나가면 전투에서 제외된다. 남은 병력은 보존된다.
- 퇴각 중에는 등을 보이므로 추격하는 쪽이 **배후 공격 보정**을 자연스럽게 받는다.

**② 포로 (장수가 포위되어 잡힘)**
- 장수가 있는 중앙 소부대가 **적 병사에게 둘러싸이면** 포로가 될 수 있다.
- 포위 판정: 장수 주변 일정 반경 안에서 적 병사가 차지한 방향 비율이 기준 이상(예: 75%)이고, 장수 주변 아군 병력이 기준 이하일 때.
- 포위 상태가 지속되는 동안 포로 확률이 쌓인다. 장수 **무력**이 높으면 포위를 뚫고 탈출할 확률이 높다.
- 장수가 포로가 되면 그 군단은 **궤멸**한다 (남은 병력은 흩어져 전투에서 제외).

**공통**
- 퇴각이나 포로가 발생하면 근처 아군 군단의 사기가 떨어진다 (가산 보정에 반영).
- 장수는 죽지 않는다. 결과는 퇴각 / 포로 중 하나로 `BattleResult`에 기록된다.
- 포로가 된 장수의 이후 처리는 [captivity.md](captivity.md) 참고.

### 2.5.2 포로 처리 (전투 이후)

전투 이후의 포로 처리(아군 구출, 적 등용·해방)는 [captivity.md](captivity.md)로 분리했다.

### 2.6 장수 능력치와 지휘 보너스

모든 능력치는 1~100, 소수점 허용.

장수 능력치도 **데이터로 정의하는 확장형**이다. 첫 버전 항목:

| 능력치 | 역할 |
|---|---|
| 통솔 | **규율**: 명령 반응 속도, 진형 유지, 성새전 방어, 지휘 범위 |
| 무력 | 야전 공격력, 일기토, **용맹**, **사기가 높을 때 공격 가산** (2.5) |
| 지략 | 소부대 **판단력** 보너스, **스킬 사용 조건**(어려운 스킬일수록 높은 지략 필요), **사기가 높을 때 방어 가산** (2.5) |
| 성향 | 퇴각 기준 |

나중에 정치·매력처럼 전략 화면용 능력치가 추가돼도 같은 방식으로 붙인다.

**장수 → 소부대 영향**

소부대의 최종 능력치는 장수 능력치의 영향을 받는다. 어떤 장수 능력치가 어떤 소부대 능력치에 얼마나 영향을 주는지는 **영향표(데이터)**로 정의한다.

| 장수 능력치 | 소부대에 주는 영향 (초안) |
|---|---|
| 통솔 | 방어, 반응 속도, 응집력, 추격 억제 |
| 무력 | 공격, 사기, 돌파력 (+ 지휘 이탈 경향) |
| 지략 | 판단력, 인지 반경 |

- 영향 크기는 **지휘 범위**에 따라 줄어든다 (장수와 멀수록 약함).
- 새 능력치가 추가되면 영향표에 줄만 추가한다.

장수 능력치에서 군단 전체에 영향을 주는 두 축을 만든다.

| 축 | 계산 (초안) | 효과 |
|---|---|---|
| **규율** | 통솔 위주 + 지략 일부 | 명령 반응 지연 감소(즉각 이동), 진형 응집력, 진형 전환 시간 단축, 추격 억제(진형 이탈 감소) |
| **용맹** | 무력 위주 | 공격력·돌파력, 사기 상승·유지, 돌격 피해 |

- **용맹이 규율보다 크게 높으면** 소부대가 지휘 체계를 약간 벗어난다.
  - 추격 거리가 늘어나 적을 쫓아 진형 밖으로 나간다.
  - 가끔 명령보다 눈앞의 적을 우선한다 (독자 행동 확률).
  - 예: 맹장형. 돌격은 강하지만 진형이 흐트러지고 측면이 빈다.
- **규율이 높으면** 명령 즉시 반응하고 진형이 무너지지 않는다.
  - 예: 책사형. 화력은 약해도 상성 좋은 진형으로 바꾸는 속도가 빨라 진형 싸움에서 이긴다.
- **균형형**은 둘 다 적당히 받는다.

추가 규칙 (채택 확정):

| 규칙 | 내용 |
|---|---|
| 지휘 범위 | 장수(중앙 소부대)와 가까운 소부대일수록 보너스를 크게 받는다. 통솔이 높으면 범위가 넓다. 진형 선택에 의미가 생긴다 (언월은 장수가 앞에 있어 선봉이 보너스를 받음) |
| 진형 숙련도 | 장수별로 잘 쓰는 진형을 데이터로 지정해 전환 시간·응집력 보너스 |
| 특성 태그 | `맹장`, `신중`, `기습` 같은 태그로 보정치를 묶어 데이터로 붙인다. 새 특성은 JSON만 추가 |
| 장수 피격 | 무력이 낮은 장수(문관)가 직접 공격받으면 사기 급락 (원작 요소) |

### 2.7 일기토

- 야전 시작 직전에 조건부 발생하는 이벤트. 스위치 `duel`.
- 기본 조건: 두 장수의 무력 차이 3 이내이면 높은 확률. 책사형 장수는 거부.
- **운이 주가 되는 가위바위보식 대결** (확정 방향). 능력치는 조금만 영향을 준다.

#### 2.7.1 진행

- 두 장수 모두 **체력 100**, **기운 0%**으로 시작.
- 매 라운드 **3, 2, 1 카운트** 동안 각자 행동을 고른다 (상대 선택은 안 보임). 동시에 공개하고 결과를 적용한다.
- 시간 안에 못 고르면 무작위로 고른다.
- 한쪽 체력이 0이 되거나, 한쪽이 퇴각에 성공하거나, 최대 라운드(예: 10)가 지나면 끝. 최대 라운드면 체력이 많은 쪽 승리.

#### 2.7.2 행동 (제안)

| 행동 | 설명 |
|---|---|
| **공격** | 기본 공격 |
| **회피** | 공격·활을 피하고 기운을 얻음 |
| **기운 모으기** | 기운을 채움. 대신 공격·활에 무방비 |
| **활쏘기** | 원거리 공격. 퇴각하는 상대에게 치명적 |
| **퇴각** | 일기토에서 빠짐. 활에 맞으면 위험 |
| **필살** | **기운 100%일 때만** 선택 가능. 큰 피해, 회피 불가. 기운을 모두 씀 |

- **별도 '방어' 행동은 두지 않는다** (확정). 회피가 방어 역할을 맡는다. 필요하면 나중에 데이터(`contests.json`)로 추가한다 (예: 피해 30%만 받고 필살을 막지만, 상대가 마음 놓고 기운을 모으는 행동).

#### 2.7.3 결과표 (행: 나, 열: 상대 — 표의 내용은 "나"에게 일어나는 일)

| 나 ＼ 상대 | 공격 | 회피 | 기운 모으기 | 활쏘기 | 퇴각 | 필살 |
|---|---|---|---|---|---|---|
| **공격** | 무력이 높은 쪽이 **차이만큼** 상대 체력을 깎음 | 빗나감, 상대 기운 +20% | 상대에게 **큰 피해**(×1.5) | 상대에게 피해 (활을 끊음) | 상대 퇴각 성공 | 내가 필살에 맞음 |
| **회피** | 피함, 내 기운 +20% | 아무 일 없음 | 상대 기운 +50% | 피함, 내 기운 +20% | 상대 퇴각 성공 | **못 피함**, 필살에 맞음 |
| **기운 모으기** | 내가 큰 피해 | 내 기운 +50% | 둘 다 기운 +30% | 내가 활에 맞음 | 상대 퇴각 성공 | 내가 필살에 맞음 |
| **활쏘기** | 내가 피해 | 상대가 피함 | 상대가 활에 맞음 | 둘 다 활에 맞음 | **상대 체력 절반 깎음, 절반 이하면 즉시 쓰러짐** | **필살을 끊고** 상대에게 피해 |
| **퇴각** | 퇴각 성공 | 퇴각 성공 | 퇴각 성공 | **체력 절반 잃음, 절반 이하면 즉시 쓰러짐** | 둘 다 물러남 (무승부) | 퇴각 성공 |
| **필살** | 상대에게 큰 피해 | 상대에게 큰 피해 | 상대에게 큰 피해 | 필살이 끊기고 내가 피해 | 상대 퇴각 성공 | 둘 다 큰 피해 |

- 물고 물리는 관계: 공격 > 기운 모으기 > 회피 > 공격, 활쏘기 > 퇴각·필살, 필살 > 공격·회피·기운 모으기.
- 기운을 다 채우면 상대도 "필살이 온다"는 걸 알기 때문에, 활쏘기나 퇴각으로 맞서는 수 싸움이 생긴다.

#### 2.7.4 운과 능력치

- 모든 피해에 **무작위 폭**을 둔다 (예: ±30%). 가끔 **회심**(예: 10%, 피해 ×2).
- 무력은 공격 대 공격의 차이와 피해량에 **조금만** 반영한다 (예: 피해 ±20% 이내). 운이 주가 되게 한다.
- 무작위는 고정 시드 난수를 쓴다 (리플레이·서버 재현·대전 동기화).

#### 2.7.5 결과가 전투에 주는 영향 (확정)

| 결과 | 영향 |
|---|---|
| 승리 | 내 군단 사기 상승, 상대 군단 사기 크게 하락 |
| **퇴각** | 퇴각한 장수의 군단 **사기 저하** |
| **패배 (체력 0)** | 패배한 장수의 군단이 **몇 초간 혼란 상태에 빠진 뒤 도망**(퇴각)한다 |
| 무승부 (둘 다 물러남) | 영향 없음 |

- 패배한 장수는 **포로가 될 수 있다** (확정, 스위치 `duelCapture`, 포로 스위치 전체는 [captivity.md](captivity.md) 3장).
- 유저 대전에서는 두 유저가 각자 고른다. 비동기 대전·적 장수는 AI가 고른다 (체력이 적으면 퇴각, 기운이 차면 필살 경향 등).

### 2.7.6 논쟁 (지략 대결) — 확정

일기토의 **지략판**. 무력이 낮아 일기토를 거부하는 책사형 장수끼리 말과 꾀로 겨룬다.

- 발생: 야전 시작 직전, 두 장수의 **지략 차이가 일정 이내**일 때 확률로 (일기토와 같은 방식). 스위치 `debate`.
- 진행: 일기토와 **똑같은 틀**. **평정심 100**, **통찰 0%**, 3·2·1 동시 선택, 운이 주가 됨 (지략은 조금만 반영).

| 논쟁 행동 | 일기토의 대응 행동 | 설명 |
|---|---|---|
| **강한 설득** | 공격 | 논리로 몰아붙여 상대 평정심을 깎음 |
| **흘려듣기** | 회피 | 상대의 강한 설득을 받아넘기고 통찰을 얻음 |
| **심사숙고** | 기운 모으기 | 통찰을 채움. 대신 강한 설득에 무방비 |
| **조롱** | 활쏘기 | 상대를 자극. 물러서는 상대에게 치명적 |
| **논쟁 철수** | 퇴각 | 논쟁에서 물러남 |
| **세뇌** (필살) | 필살 | 통찰 100%일 때만. 큰 타격, 흘려듣기 불가. 조롱에 끊김 |

- 결과표는 일기토 결과표(2.7.3)와 같다. 이름과 수치만 다르다.
- 버튼에 이름이 길면 짧게 표시한다 (예: 설득, 철수). 이름은 테마 문자열이라 코드 수정 없이 바꾼다.
- **세뇌로 이긴 경우**, 그 상대 장수가 이번 전투에서 포로가 되면 **등용 성공률 보너스** (확정, 수치는 설정값).

**결과가 전투에 주는 영향**

| 결과 | 영향 |
|---|---|
| 승리 | 상대 장수 **책략 점수 감소**, 내 책략 점수 증가, 양측 사기 소폭 변화 |
| 논쟁 철수 | 철수한 장수 군단 사기 소폭 저하 |
| 패배 (평정심 0) | 패배한 장수 **책략 점수 크게 감소** + 사기 저하 (몸싸움이 아니므로 혼란·도망은 없음) |

- 성장: 장수 키우기의 **논쟁** 항목에서 전적에 따라 보상 (예: 100승마다 지략 +1). 보상 수치는 나중에 입력.

### 2.7.7 대결 엔진 (공통)

- 일기토와 논쟁은 **하나의 대결 엔진**을 쓰고, **행동 목록·결과표·영향은 데이터**로 정의한다 (`contests.json`).
- 새 대결(예: 판타지 테마의 마법 대결)은 데이터만 추가하면 된다.

### 2.8 스킬

- 장수가 가진 스킬을 전투 중 사용한다. 기존 "책사 자동 전술"은 스킬의 한 종류로 흡수한다.
- **대상·위치 지정**: 4.2 참고.
- **보유 스킬은 전부 가지고 출진한다** (확정). 미리 고르는 단계는 없다.

**사용 제한: 책략 점수 + 사용 횟수** (확정, 재사용 대기시간 없음)

| 제한 | 내용 |
|---|---|
| **책략 점수** | 장수마다 전투 시작 시 **지략(지력) 값만큼** 점수를 가진다. 예: 지략 80 → 80점 |
| **점수 회복** | **사기가 높을 때 천천히 회복**한다 (확정). 기준 사기·회복 속도는 설정값. **켜고 끌 수 있다** (`skillPointRegen`, 2.20) |
| **스킬 비용** | 스킬마다 점수 비용이 있다. 예: 간파 15, 복병 25, 화계 40 |
| **사용 횟수** | 스킬마다 **한 전투에서 쓸 수 있는 횟수**가 정해져 있고, 버튼에 **숫자로 표시**한다. 스텝 데이터로 덮어쓸 수 있다 |

- 점수와 횟수가 **둘 다** 남아 있어야 쓸 수 있다. 지략이 높은 장수는 더 많이, 더 비싼 스킬을 쓸 수 있다.
- 실패하거나 중간에 취소해도 점수와 횟수는 소모된다. 그래서 신중하게 써야 한다.
- 전투 화면: 장수 책략 점수 막대 + 스킬 버튼마다 (비용 · 남은 횟수).

**발동 조건과 준비** (제안 유지)
- **복병**: 숲에 들어가 **들키지 않은 채 일정 시간 머물러야** 매복이 완성된다. 중간에 풀면 소모된 점수·횟수는 돌아오지 않는다.
- **화계**: 바람이 있고 비가 오지 않는 숲에서만 쓸 수 있다.
- 일반 공격은 숲에 불을 붙이지 않는다. 불은 화계·화전 일제사격 같은 **스킬로만** 붙는다.

**그 밖**
- **사용 조건**: 스킬마다 요구 능력치를 둔다 (예: 지략 70 이상). 레벨·병종 조건도 가능.
- **구성**: 스킬 = 요구 조건 + 점수 비용 + 사용 횟수 + 발동 조건 + 대상 + **효과 목록**.
- **효과는 조립식**: 피해, 버프, 디버프, 사기, 진형 혼란, 이동, 은신, 기습, 드러내기 등. 새 스킬은 대부분 데이터 추가로 만든다.
- 위력은 능력치에 비례할 수 있다 (예: 화계 피해 = 지략 × 계수).
- 위임 상태에서는 AI가 같은 제한 안에서 자동으로 쓴다.
- (선택) 지략 대결 성공 판정: 시전자 지략 vs 상대 장수 지략으로 성공 확률. 처음에는 넣지 않고 나중에 추가 가능.

### 2.9 능력치 확장 구조

장수 능력치와 소부대 능력치 모두 같은 방식으로 다룬다.

- 능력치 항목은 `stats.json`에서 정의한다: id(영문), 최소·최대, 기본값. **화면에 보이는 이름은 테마 문자열**에서 가져온다 ([../theme.md](../theme.md)).
- 장수·소부대·병종 데이터는 `{ "leadership": 82.5, "might": 60 }`처럼 **이름-값 목록**으로 능력치를 가진다. 없는 항목은 기본값을 쓴다.
- 보정은 **보정 목록**으로 쌓는다: 출처(장수 영향, 진형, 명령, 특성, 스킬) + 대상 능력치 + 더하기/곱하기 값.
- 새 능력치 추가 순서: `stats.json`에 항목 추가 → 데이터에 값 입력 → 그 능력치를 쓰는 규칙(행동, 공식) 추가. 기존 코드는 고치지 않는다.

### 2.10 시야와 전장 안개

- 맵은 기본적으로 **보이지 않는다** (전장 안개). 안개 여부는 **스텝별 맵 데이터**에 포함한다 (`fogOfWar`, 기본 켜짐).
- 시야는 **부대마다 다르다.** 소부대마다 시야 능력치가 있고, 그 범위 안만 보인다.

**시야를 정하는 요소** (모두 보정 목록으로 쌓음)

| 요소 | 영향 (초안) |
|---|---|
| 소부대 시야 능력치 | 기본 시야 거리 |
| 병종 | 기병·척후병은 넓고, 중보병은 좁음 |
| 장수 | 지략이 높으면 시야·탐지 보너스 (지휘 범위 안) |
| 지형 | 언덕 위는 넓어짐, 숲 안은 좁아짐, 숲 속 적은 가까이 가야 보임 |
| 진형·명령 | 수비 중 시야 약간 증가, 돌격 중 감소 등 |
| 날씨·시간 (확장) | 비·안개·야간에 감소 |

**척후병**
- 척후병은 병종의 하나다 (태그 `척후`). 약하고 작지만 빠르고 **시야·탐지가 높다.**
- 소부대 슬롯 하나를 척후병으로 두면 군단의 시야가 크게 넓어진다. 대신 전투력이 줄어든다.
- 척후병을 먼저 지점으로 보내 정찰하는 **"척후 파견" 스킬**도 둔다 (지점 스킬, 4.2 방식).

**보이는 상태 (3단계)**

| 상태 | 화면 |
|---|---|
| 미탐색 | 어둡게 가림 |
| 탐색했지만 지금은 안 보임 | 지형만 보이고, 적은 **마지막으로 본 위치**에 흐린 표시 |
| 지금 보임 | 모두 보임 |

**탐색 기억 (같은 스텝 재도전)**
- 한 번 시야를 확보한 지역은 **그 스텝을 다시 할 때 처음부터 보인다** (확정). 스텝별로 세이브에 저장한다.
- 재도전 시작 상태: 지난 전투들에서 확보한 지역은 "탐색함" 상태로 시작한다. 지형이 보이고, 적은 지난 전투의 **처음 목격 위치**를 흐리게 표시한다 (제안).
- 실제로 지금 보이는지(적의 현재 움직임)는 여전히 아군 시야로 판정한다.
- 기억 수준은 설정값으로 바꿀 수 있다: 지형만 / 지형 + 목격 위치(제안) / 완전 공개.

**누가 무엇을 아는가**
- 플레이어 화면: **아군 전체 시야를 합친 것**을 보여준다.
- 소부대·군단의 자율 판단(2.2.2)과 AI도 **아군 전체 시야를 공유**한다 (확정). 부대마다 다른 것은 **보는 범위**(시야 능력치)이고, 본 정보는 아군 모두가 함께 안다.
- 적 AI도 같은 규칙을 따른다 (적도 안개 속에서 싸움).

**숨기와 탐지**
- 복병 같은 은신 상태의 부대는 시야 안에 있어도 **탐지 능력이 충분한 부대가 가까이 가야** 보인다.
- 척후병과 지략 높은 장수가 은신을 잘 찾아낸다.

**조작과의 관계**
- 보이지 않는 적은 터치로 선택하거나 공격 대상으로 지정할 수 없다. 빈 땅(이동·지점 스킬)은 안개 속이라도 지정할 수 있다.
- 미니맵도 안개를 그대로 반영한다.

**성능**
- 시야 계산은 맵 격자 단위로, 매 프레임이 아니라 일정 주기(예: 초당 5회)로 갱신한다.

### 2.11 이동과 충돌

- **군단은 장수를 따라간다.**
  - 경로는 **장수 기준으로 한 번만** 찾는다 (군단 단위 경로 탐색).
  - 소부대는 장수를 기준으로 한 **진형 자리**를 따라가고, 병사는 자기 소부대를 따라간다.
  - 병사 수백 명이 각자 길을 찾지 않으므로 3D 모바일에서도 가볍다.
- **충돌**
  - 병사끼리는 서로 밀어내는 간단한 회피로 겹치지 않게 한다.
  - 다른 군단은 장수 경로 탐색에서 움직이는 장애물로 다룬다. 아군 군단은 비켜 가고, 적 군단과 부딪히면 교전이 시작된다.
- **좁은 길 (다리·협곡)**
  - 진형 폭보다 길이 좁으면 군단이 자동으로 **긴 줄(종대)로 바뀌어** 통과하고, 넓은 곳에 나오면 원래 진형으로 돌아간다.
  - 통과 중에는 진형이 흐트러진 상태라 공격받으면 불리하다 (다리 앞 매복이 의미를 가짐).
- **방향 전환**: 진형은 장수가 바라보는 방향을 기준으로 회전한다. 회전 속도는 응집력·규율(통솔)에 따라 다르다.
- **교전 중**: 소부대는 자율 판단(2.2.2)에 따라 진형 자리를 벗어나 싸우고, 교전이 끝나면 자리로 돌아온다.

### 2.12 원거리 공격

- **사거리는 병종 능력치 "공격 거리"로 정한다** (보병 1, 창병 2, 궁병 10 등, 2.16). 원거리 규칙은 공격 거리가 일정 값 이상인 병종에 적용된다.
- 사거리에 붙는 보정 (가산, 설정값):

| 요소 | 영향 (초안) |
|---|---|
| 병종 | 노병·연노병은 길게, 궁기병은 짧게 |
| 장수 | 특성·스킬로 증가 가능 |
| 높이 | 언덕·성벽 위에서 쏘면 증가 |
| 날씨 (확장) | 비·강풍 시 감소 |

- **보이는 적만 쏠 수 있다.** 시야는 아군 전체 공유이므로, 다른 아군이 본 적도 사거리 안이면 쏠 수 있다 (척후병과 궁병의 조합이 의미를 가짐).
- 기본값 (조정 가능):
  - 아군 머리 위로 곡사해서 쏠 수 있다 (궁병을 후열에 두는 진형이 성립).
  - 아군 오사는 기본 꺼짐 (`balance.json` 옵션).
  - 숲 속 적은 맞히기 어렵다 → 지형 보정(가산)으로 피해 감소.
  - 성벽 위 궁병은 높이 보정과 방어 보정을 함께 받는다.
- 화살은 화면에 궤적으로 보이지만, 피해는 병력 숫자로 계산한다 (2.4).

### 2.13 상태 표시 (병사 몸에 표시)

머리 위 아이콘·막대는 다른 병사를 가리므로 쓰지 않는다. 상태는 **병사 몸 자체**로 보여준다.

| 상태 | 몸 표시 (초안) |
|---|---|
| 사기 높음 | 기본 색, 당당한 자세, 빠른 걸음 |
| 사기 낮음 | 색이 바래고(채도 감소) 움츠린 자세, 느린 걸음, 뒤돌아보는 동작 |
| 사기 붕괴 직전 | 일부 병사가 도망치는 동작 |
| 버프 | 몸 테두리에 옅은 빛 (예: 금색) |
| 디버프·혼란 | 몸 테두리 다른 색 (예: 보라), 흔들리는 동작 |
| 은신(복병) | 반투명 (아군에게만 보임) |
| 선택됨 | 발밑 링 (2.4.1 선택 표시) |

- 색만으로 구분하지 않고 **자세·동작을 함께** 바꿔서 색약 사용자도 알아볼 수 있게 한다.
- 병사별 색·테두리는 셰이더 값으로 처리해 대량 병사에서도 가볍다.
- 정확한 수치(병력·사기 숫자)는 군단을 선택하면 하단 패널·카드에서 본다.
- 병력은 병사 수 자체로 보인다 (2.4).

### 2.14 진형·스킬 습득

- 전투에서 쓸 수 있는 진형과 스킬은 **장수 키우기·부대 키우기에서 배운 것만** 나온다.
- 키우기 탭이 TO-BE인 동안에는 **초기 지급으로 배운 진형·스킬 + 스토리 보상으로 얻은 것**을 쓴다. 키우기 탭이 생기면 거기서 배운 것이 더해진다 (전투 코드는 "사용 가능 목록"만 받으므로 수정 없음).
- 전장 안개 같은 맵 조건은 **스텝별 맵 데이터에 포함**한다 (2.10).

### 2.15 군량 (전투 길이)

- 전투 길이는 고정 제한 시간이 아니라 **군량**으로 정한다.
- 군단은 전투 시간 동안 군량을 소비한다. **소비량은 부대 인원에 비례한다.**
- **기본 소비 규칙 (설정값):**
  - 병사 1명이 하루에 군량 **1**을 먹는다.
  - 전투 시간 **1분 = 1주(7일)**.
  - 따라서 병사 1명은 전투 1분에 군량 7을 소비한다.
  - 예: 병력 10,000 군단 → 1분에 70,000, 3분에 210,000. 군단 3개면 3분에 630,000.
- **특수 병사 확장**: 병종 데이터에 하루 소비량(`supplyPerDay`)을 둔다. 기본 1, 특수 병종은 2·3 등.
- 전투 화면 시간 표시에 경과 일수(예: "3주차")를 함께 보여줄 수 있다 (1분 = 1주).
  - 게임 시간 기준이므로 배속을 올려도 같은 양을 소비한다.
- 군량이 바닥난 군단은 **사기가 계속 떨어지고**(가산 보정), 기준 아래로 내려가면 **자동 퇴각**한다 (확정).
- 적군도 스텝 데이터에 군량을 가진다. 적 군량이 먼저 떨어지면 적이 퇴각한다 → **버티기(지구전)** 전술이 성립한다.
- 확장 아이디어: 적 보급을 끊는 스킬(군량 화계 등), 군량 보충 스킬.

**군량은 게임 진행 자원이기도 하다**
- 플레이어는 군량을 보유하고, **출진할 때 군량이 있어야** 전투를 시작할 수 있다.
- **출진 군량은 자동 계산**한다. 기본은 **약 3분** 동안 싸울 수 있는 양이다 (출전 병력 × 시간당 소비량 × 3분, 기본 시간은 설정값).
- 출진 화면에서 플레이어가 **늘리거나 줄일 수 있다.** 많이 가져가면 오래 버티고, 적게 가져가면 보유 군량을 아낀다.
- 출진 시 가져갈 군량이 차감되고, 남은 군량은 전투 후 돌려받는다 (제안 유지).
- 군량은 **앱 결제**로 구매할 수 있다 (상점, 추후).
- **시간 회복**: 기본으로는 없다. 사용자가 **특수 패키지를 구입하면** 시간이 지나면서 군량이 회복된다 (패키지 내용·회복 속도는 추후).
- **승리 보상 = 적 군량 포획**: 이기면 적이 쓰지 못하고 남긴 군량을 가져온다. **빨리 이길수록 적 군량이 많이 남아 있으므로 보상이 커진다.**
  - 궤멸·포로가 된 적 군단의 군량은 전부 포획한다.
  - **퇴각한 적 군단은 살아남은 병사 몫만 가지고 가고, 나머지는 몰수한다.**
    - 가져가는 양 = 남은 군량 × (퇴각 시 병력 ÷ 출전 병력)
    - 예: 출전 9,000 → 퇴각 시 3,000, 남은 군량 90,000 → 30,000을 가지고 가고 60,000을 몰수.
    - 많이 쓰러뜨린 뒤 퇴각시킬수록 몰수량이 커진다.
  - 포획률은 설정값 (기본 100%).
  - 실력 있는 플레이어는 결제 없이도 군량을 늘릴 수 있는 경로가 된다.

### 2.16 병종 특성과 지형 규칙 (이동 가능 지역)

**병종마다 능력치가 다르다** (확정). 모든 값은 병종 데이터(`troopTypes.json`)에 입력하고, 레벨·장수·진형·상성 보정이 더해진다.

| 능력치 | 예 (초안) |
|---|---|
| 공격력, 방어력 | 병종별 기본값 |
| 이동 속도 | 기병 빠름, 투석기 느림 |
| **공격 거리** | **보병 1, 창병 2, 궁병 10** (모든 병종이 가진다. 근접도 거리로 표현) |
| 시야, 탐지 | 첨병(척후병) 높음 |
| **진형 변경 속도** | 병종·훈련도에 따라 다름 (장수 규율 보정이 더해짐) |
| 하루 군량 소비 | 기본 1, 특수 병종 2·3 |

**이동 가능 지역: 병종 × 지형 규칙표** (확정)

병종이 어떤 지형에 들어갈 수 있는지, 들어가면 어떤 보정을 받는지를 **표(데이터)**로 정한다. 병종 대신 **태그**로 지정하면 새 병종도 자동 적용된다.

| 병종(태그) | 지형 | 규칙 (예) |
|---|---|---|
| 기병 `mounted` | 성벽 | **진입 불가** |
| 투석기 `siege` | 산 | **진입 불가** |
| 산악병 `mountaineer` | 산 | 이동 속도 **가산**, 방어 가산 |
| 모든 병종 | 건물 | **진입 불가** (전장마다 예외 지정 가능) |
| 기병 `mounted` | 숲 | 이동 비용 증가, 돌격 위력 감소 |
| 보병 계열 | 강 얕은 곳 | 느리게 통과 |

**전장 유형별 출전 제한** (확정)
- 전장 유형마다 출전할 수 없는 병종(태그)을 정한다. 예: **해상전에는 기병 투입 불가**.
- 출진 준비 화면에서 제한된 병종이 든 소부대는 표시하고 막는다.

규칙표 항목: 진입 가능 여부, 이동 비용 배율, 공격·방어 보정(%p), 시야 보정. 새 지형·병종은 표에 줄을 추가한다.

### 2.17 바람과 화계 (변하는 지형)

**바람**
- 맵마다 바람 방향과 세기를 가진다 (스텝 데이터). 전투 중 바뀔 수도 있다 (이벤트).
- 화면에 바람 방향을 표시한다.

**화계** (대표 스킬)
- 지정한 지점에 불을 놓으면 **바람 방향으로 불이 번지며 나무(숲)를 태운다.**
- **탄 숲은 사라진다** (지형이 "불탄 땅"으로 바뀜): 숨을 곳·엄폐·시야 가림이 없어지고, 이동 비용도 바뀐다.
- 불이 지나가는 칸에 있는 부대는 피해를 입는다. **숲에 숨어 있던 복병도 피해를 입고 드러난다.**
- 등갑병처럼 불에 약한 병종은 추가 피해.
- 바람이 바뀌면 불이 아군 쪽으로 번질 수도 있다 (위험 부담).
- 확장: 비 날씨에는 화계 약화, 강·불탄 땅에서는 불이 멈춤.

### 2.18 복병과 간파 (대표 상호작용)

- 복병은 **간파 스킬로만** 미리 찾아낼 수 있다 (확정). 첨병이 지나가기만 해서는 발견되지 않는다.
- **간파 스킬** (예: 스타크래프트 스캔처럼):
  - 지정한 지점 주변을 **몇 초간 밝혀서 숨은 부대까지 드러낸다.**
  - 책략 점수와 사용 횟수를 쓴다. 안개 속 지점에도 쓸 수 있다.
  - 첨병의 역할: 넓은 **시야**로 의심 지점을 찾아내고, 간파 범위를 넓혀 준다 (제안). 숨은 부대를 직접 찾지는 못한다.
- **간파하지 않고 복병이 있는 숲을 지나가면** 복병을 만난다:
  - 일부 병사가 **몇 초간 혼란** 상태(헤롱거림)에 빠진다: 이동·공격 불가 또는 크게 약화, 몸 표시는 흔들리는 동작 (2.13).
  - 혼란 비율·시간은 복병 쪽 능력·숫자와 아군 사기에 따라 정한다 (설정값).
  - 그동안 복병이 **기습 보정**을 받고 공격한다. 사기도 떨어진다.
- 상성 관계: **간파가 복병을 막고, 화계가 숲 복병을 막는다.** 둘 다 점수·횟수를 쓰므로, 어디가 수상한지 판단하는 것이 실력이 된다.

### 2.19 균형 원칙: 영원한 승자 없음

목표는 **가위바위보처럼 절대 강자가 없고, 상황에 따라 아슬아슬하게 이기는 전투**다 (확정).

**원칙**
1. **모든 강점에는 반격 수단이 있다.** (아래 반격표)
2. **강점에는 대가가 있다.** 첨병을 넣으면 전투력이 줄고, 화계는 내 숲도 태우고, 기병은 성벽·숲에서 약하다.
3. **보정은 상한이 있다.** 유리한 조건이 겹쳐도 보정 합계 상한 때문에 압도적 차이가 나지 않는다 (2.4.2).
4. **정보가 승패를 바꾼다.** 전장 안개 때문에 상대 구성을 알아야(정찰) 반격을 고를 수 있다.
5. **맵이 답을 바꾼다.** 같은 편성도 숲이 많은 맵, 산이 많은 맵, 강·성벽 맵에서 강약이 달라진다. 스텝마다 맵이 다른 답을 요구하도록 설계한다.

**반격표 (초안, 계속 추가)**

| 강점 | 반격 수단 |
|---|---|
| 기병 돌격 | 창병, 방원진, 숲·성벽 지형 |
| 창병 | 궁병 |
| 궁병 | 기병, 숲 엄폐, 방패병 |
| 숲 복병 | 간파 스킬, 화계 |
| 화계 | 바람 읽기, 강·불탄 땅으로 이동, 비 날씨(확장) |
| 등갑병 (물리 방어) | 화계 |
| 성벽 수비 | 투석기, 군량 끊기(지구전) |
| 투석기 | 기병 기습 (투석기는 느리고 근접에 약함) |
| 산악병 | 산 밖 평지로 끌어내기 |
| 대군 | 좁은 길·다리(종대 강제), 복병 |
| 진형 | 상성 진형 (2.2.1) |

**검증**
- 밸런스 시뮬레이터에 **"절대 강자 탐지"**를 넣는다: 여러 편성 × 여러 맵을 자동 대전시켜, 어떤 편성이 모든 맵에서 일정 승률(예: 65%) 이상이면 경고.
- 같은 능력치에서 진형 상성·병종 상성대로 승패가 나오는지 회귀 테스트 (기존).

### 2.19.1 성장 방향: 장수 레벨은 키우기 탭, 전투는 부대 결속

**장수 레벨업** (확정)
- 장수 레벨은 주로 **장수 키우기 탭**에서 올린다.
- 전투로도 레벨이 오를 수 있지만 **아주 더디게** 한다. 전투 레벨업 자체를 **켜고 끌 수 있다** (`battleLevelUp`).
- 레벨업 시 능력치는 **성장률 방식**: 장수마다 정해진 비율로 오르고 **무작위가 없다**. 결과를 예측할 수 있어 고용 판단·대전 공정성에 유리하다.

**부대 결속(응집)** (확정)
- 전투에서 **승리할수록 부대의 결속**이 쌓인다. 장수 레벨이 아니라 **부대**에 붙는 값이다.
- 결속이 높을수록:

| 효과 | 내용 |
|---|---|
| **상태이상 회복** | 혼란 등 상태이상에서 **더 빨리 회복** (회복 보정) |
| 상태이상 저항 | 혼란에 걸리는 병사 비율 감소 |
| 진형 유지 | 교전 중 대형이 덜 흐트러짐 |

- 결속은 부대에 붙어 있어 **누가 이끌어도 유지**되고, 부대 고용 스냅샷에도 포함된다 (결속 높은 부대 = 고용 가치↑).
- 패배하면 결속이 **조금 줄어든다** (확정, 감소량은 설정값).
- 켜고 끌 수 있다 (`cohesionGain`).

**훈련도와 결속의 차이**

| 값 | 쌓는 방법 | 주요 효과 |
|---|---|---|
| 훈련도 | 부대 키우기 탭 (훈련) | 진형 변경 속도, 판단력, 반응 속도, 승급 조건 |
| **결속** | **전투 승리** | 상태이상 회복·저항, 진형 유지 |

### 2.20 규칙 스위치 (켜고 끄기)

**웬만한 규칙은 켜고 끌 수 있게 만든다** (확정). 테스트·밸런스 조정·모드(스토리, 대전)별로 규칙을 넣었다 뺐다 하기 위해서다.

- 규칙마다 **켜기/끄기 값(true/false)**을 `balance.json`에 둔다.
- 스텝 데이터와 **규칙 세트**(대전 모드 등)가 이 값을 덮어쓸 수 있다.
- 꺼진 규칙은 계산에서 빠지고 화면 표시도 숨긴다. 다른 규칙은 영향을 받지 않게 각 규칙을 독립적으로 만든다.
- 실시간 조정 패널(개발용)에서 전투 중에도 바꿔 볼 수 있다.
- 자동 테스트는 주요 스위치를 켠 경우와 끈 경우를 모두 돌린다.

첫 버전 스위치 목록 (계속 추가):

| 스위치 | 규칙 | 기본 |
|---|---|---|
| `fogOfWar` | 전장 안개 | 켜짐 |
| `fogMemory` | 재도전 시 확보한 시야 유지 | 켜짐 |
| `skillPointRegen` | 사기가 높을 때 책략 점수 회복 | 켜짐 |

### 4.1 터치 조작: 전장에서 부대 선택

- 전장의 부대를 **직접 터치해서 선택**할 수 있다. 하단 카드나 ◀ ▶ 버튼으로 고르는 것과 결과가 같다.
- **터치 영역 = 그 군단의 모든 부대원 + 여유 반경.**
  - 소부대 6개의 병사 위치를 감싸는 영역에, 손가락 크기를 고려한 여유 반경(화면 기준 약 48dp, 설정값)을 더한다.
  - 병사 하나하나를 정확히 누르지 않아도, 부대원이 모여 있는 범위 안을 누르면 선택된다.
  - 소부대를 눌러도 명령 단위가 군단이므로 **그 소부대가 속한 군단이 선택**된다. 누른 소부대는 카드에서 함께 강조한다.
- **겹칠 때 우선순위:**
  1. 터치 지점에 가장 가까운 부대원이 속한 군단
  2. 거리가 같으면 아군 군단 우선
  3. 같은 자리를 다시 누르면 겹친 군단을 차례로 바꿔 선택
- **아군 군단 터치:** 지휘 대상 군단으로 선택된다 (◀ 제1군 ▶ 자리가 바뀜).
- **적 군단 터치:** 대상 적 군단으로 선택된다 (◀ 적 제1군 ▶ 자리가 바뀜). 아군 군단이 선택된 상태라면 **공격 대상 지정**(그 적을 목표로 공격 명령)이 된다.
- **빈 땅 터치:** 아군 군단이 선택된 상태라면 그 지점으로 **이동 명령**이 된다. 진형을 유지한 채 이동한다.
- 이동·공격 명령의 목적지와 대상은 전장에 표시(경로선, 목적지 표식)해서 확인할 수 있게 한다.
- **터치와 카메라 조작 구분:** 손가락이 일정 거리(설정값) 이상 움직이면 드래그(카메라 이동), 두 손가락이면 핀치 확대, 짧게 떼면 터치(선택)로 판정한다.
- **선택 표시:** 선택된 군단의 부대원 발밑에 표시(링)를 띄우고, 하단 카드와 패널도 동시에 바뀐다. UI에서 고르든 전장에서 고르든 **선택 상태는 한 곳에서 관리**하므로 항상 일치한다.
- 터치 반경, 드래그 판정 거리 등은 설정값으로 둔다.

### 4.2 스킬 사용: 대상·위치 지정

스킬은 대상과 위치를 지정해서 쓸 수 있다. 일시정지 중에도 지정할 수 있다.

**스킬 대상 종류** (`skills.json`의 `target`)

| 대상 | 예 |
|---|---|
| 자신 | 사기 회복, 진형 강화 |
| 아군 군단 | 지원 버프 |
| 적 군단 | 화계, 도발, 혼란 |
| 지점 | 복병, 함정 |
| 범위 | 낙석, 화살비 (지점 + 반경) |
| 방향 | 돌파 (직선) |

**사용 흐름**
1. 아군 군단을 선택하고 스킬 버튼을 누르면 **지정 모드**가 된다. 사거리와 효과 범위가 전장에 미리 보인다.
2. 대상(적 군단·아군 군단·지점)을 터치한다.
3. 대상이 사거리 안이면 바로 사용한다.
4. 사거리 밖이면 **사거리까지 이동한 뒤 사용**한다 (자동 접근).
5. **지점 스킬**(예: 복병)은 지점을 누르면 선택지가 뜬다.
   - **이동만**: 그 지점까지 이동만 한다.
   - **도착 후 사용**: 그 지점에 도착하면 스킬을 쓴다.
6. 스킬 버튼을 다시 누르거나 취소를 누르면 지정 모드를 끝낸다.

**명령 예약 (순서대로 실행)**
- 군단은 명령을 **줄지어 예약**할 수 있다. 예: 이동 → 도착 후 복병 사용.
- 예약된 명령은 경로선과 목적지 표식(스킬 아이콘 포함)으로 보인다.
- 새 명령을 내리면 기존 예약을 대체한다 (예약 추가 방식은 미결).
- 이동 중 대상이 사라지거나 조건이 깨지면 스킬마다 정한 방식(취소 / 가장 가까운 대상으로 변경)으로 처리한다.

**스킬 데이터 예시 (복병)**

```json
{
  "id": "ambush",
  "nameKey": "skill.ambush",
  "requires": [{ "type": "statAtLeast", "stat": "intellect", "value": 60 }],
  "cost": 25,
  "usesPerBattle": 1,
  "conditions": [{ "type": "terrain", "value": "forest" }, { "type": "setupSec", "value": 20 }],
  "target": { "type": "point", "range": 0, "allowMoveOnly": true },
  "outOfRange": "approachThenCast",
  "onTargetLost": "cancel",
  "effects": [
    { "type": "stealth", "durationSec": 30 },
    { "type": "surpriseAttack", "damageMultiplier": 1.5, "moraleDamage": 15 }
  ]
}
```

## 5. 확장 구조: 전투 모듈의 입구와 출구

```
[BattleSetup] → 전투 모듈 → [BattleResult]
```

- **BattleSetup (입구)**: 지금은 스텝 JSON에서 생성. 나중에 전략 화면이 같은 형식으로 만들어 넘긴다.
- **BattleResult (출구)**: 승패, 군단별 남은 병력, 장수 상태(퇴각·부상·포로), 공적·경험치.
- 전략 화면을 붙여도 전투 코드는 수정하지 않는다.
- 전투 규칙(Model)과 표시·입력(View)을 분리한다. 규칙은 엔진에 의존하지 않는다.
