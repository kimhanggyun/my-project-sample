# 맵과 지형

> 상태: 설계 뼈대 (수치 미정) · 개발은 단계별로 순차 추가 (10장)
> 관련: [battle.md](battle.md) 2.10(시야), 2.11(이동), 2.16(병종 × 지형 규칙), 2.17(바람·날씨·화계) · [troops.md](troops.md) 5장(지형 규칙 추가분) · [skills.md](skills.md)(지형 스킬) · [ai.md](ai.md)
> 이름은 현재 테마 기준. 데이터는 영문 id.

---

## 1. 원칙

1. **맵 = 규칙 격자 + 화면(3D)의 두 층.**
   - **규칙 격자**: 지형 종류, 높이, 오브젝트, 출현 지점, 목표 구역. 전투 규칙은 이것만 본다 (엔진 무관, 데이터).
   - **화면**: 격자 위에 테마에 맞는 3D 모델을 얹어 그린다. 테마를 바꾸면 같은 격자에 다른 그림이 올라간다.
2. **조립식 지형 부품.** 맵은 부품(2장)을 배치해서 만든다. 부품의 성질은 데이터.
3. **맵이 답을 바꾼다.** 같은 편성도 맵에 따라 강약이 달라지게 설계한다 ([battle.md](battle.md) 2.19).
4. **지형은 변한다.** 불타고, 잠기고, 다리가 끊기고, 목책이 생긴다 (6장).
5. **세로 화면 기준.** 기본 배치는 아군이 아래, 적이 위 (참고 영상의 세로 통로 구도). 너무 넓은 맵은 카메라 이동 부담이 크다.

## 3. 높이 (고도)

- 높이 0~3. 높은 곳에 있으면:
  - **시야↑**, 원거리 **사거리↑**, **방어↑**.
  - 아래로 돌격하면 돌파력↑ (내리막), 위로 돌격하면 ↓.
- 높은 지형은 **뒤쪽 시야를 가린다** (언덕 너머는 안 보임). 매복과 기습이 가능해진다.
- 스위치 `heightBonus`.

## 5. 맵 유형 (템플릿)

| 유형 | 특징 | 유리한 편성·전술 | 불리한 편성 |
|---|---|---|---|
| **평원** | 넓은 평지, 언덕 몇 개 | 기병, 학익·횡진, 언덕 쟁탈 | 매복 위주 |
| **숲 지대** | 숲·풀숲 많음 | 복병, 화계, 경보병, 간파 | 기병, 중장 |
| **산악 협곡** | 산·절벽·좁은 길 | 산악병, 낙석, 매복, 고지 점령 | 대군, 기병, 투석기 |
| **강 건너기** | 강·여울·다리 | 다리 사수, 궁병, 수공, 공병(다리) | 건너는 쪽 (방어↓) |
| **늪지** | 늪·풀숲 | 경장, 궁병, 유인 | 중장·기병 |
| **성새전** | 성벽·성문·해자·망루 | 수비: 궁병·통솔 / 공격: 투석기·충차·운제·지구전 | 공격 측 기병 |
| **수상전** (확장) | 물·배 | 수군, 화선 | 기병 (투입 불가) |

- 스토리 스텝은 유형을 섞어서, 한 가지 편성만으로 계속 이길 수 없게 배치한다.

## 6. 지형 변화

| 원인 | 변화 | 되돌아감 |
|---|---|---|
| 화계·화전 | 숲·풀숲 → 불탄 땅 | 안 됨 (그 전투 동안) |
| 수공 (둑 터뜨림) | 하류 → 침수 (이동 불가·느림) | 일정 시간 후 물 빠짐 → 진흙(느림) |
| 낙석 | 좁은 길 → 막힘 | 일정 시간 후 통과 가능 |
| 다리 파괴 | 다리 → 강 | 공병이 다시 놓을 수 있음 |
| 목책 설치 | 평지 → 목책 | 불탐·파괴 |
| 성문 파괴 | 성문 → 통로 | 안 됨 |
| 비 (날씨) | 평지·길 → 진흙 (느림) | 비 그친 뒤 서서히 |

- 지형이 바뀌면 시야·이동·은신·전투 보정이 바로 다시 계산된다.
- 리플레이·대전 재현을 위해 지형 변화도 결정적이어야 한다 (고정 시드).

## 7. 맵 만드는 방법

- **기준은 규칙 격자(데이터)**: 개발용 **맵 편집기**에서 칸마다 부품·높이·오브젝트를 칠한다.
- **화면은 격자에서 자동 생성 + 손질**: 부품마다 테마 3D 모델 세트를 정해 두고, 격자대로 자동 배치한 뒤 필요한 곳만 손으로 꾸민다. 맵을 빨리 많이 만들 수 있고, 테마를 바꿀 때 격자를 그대로 쓴다.
- 맵 편집기는 구현 단계에서 정한다 (엔진 에디터 확장 또는 별도 도구).

---

## 8. 세로 화면 고려

- 기본: 세로로 긴 맵 (아군 아래 → 적 위). 가로로 넓은 맵은 카메라 이동이 많아진다.
- 크기 기준 (예): 소형 = 한 화면 반, 중형 = 두세 화면, 대형 = 네 화면 이상. 미니맵은 탭하면 펼침.
- 학익·횡진처럼 넓게 펼치는 진형을 위해 맵 폭은 최소 기준을 둔다.

---

## 9. 대전(PvP) 맵

- 공정을 위해 **대칭 맵**(위아래 또는 대각선)을 기본으로 한다.
- 출현 지점·쟁탈 지점(망루·보급소·언덕)을 같은 거리에 둔다.

## 10. 개발 순서

| 단계 | 지형·오브젝트 | 맵 |
|---|---|---|
| **1차** | 평지, 길, 풀숲, 숲, 불탄 땅, 언덕, 강, 여울, 다리, 좁은 길 | 야전 2~3개 (평원, 숲 지대, 강 건너기) |
| **2차** | 산, 절벽, 늪, 둑, 망루, 보급소, 목책 | 산악 협곡, 늪지 |
| **3차** | 성벽, 성문, 해자, 건물, 수용소 | 성새전, 구출 전투 |
| **4차** | 수상 지형 | 수상전, 대전용 대칭 맵 |

## 11. 검증

- 맵마다 편성 조합을 자동 대전시켜 **한 편성이 모든 맵에서 이기지 않는지** 확인 (절대 강자 탐지).
- 대전 맵은 양쪽 출현 지점을 바꿔 돌려서 승률이 50%에 가까운지 확인.
