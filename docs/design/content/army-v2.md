> 계기: 부대 관리 탭에 같은 병종 부대가 여러 개 보여 헷갈린다 (지금 처음 지급 13개: 보병 3·창병 3·궁병 3·기병 2·첨병 2). 사용자 제안: 계정 레벨(계급)에 따라 편성을 늘리고, 부대 관리에서는 병종별로 합쳐 보인다. 단독 부대도 진형이 바뀌어야 한다. 부대 관리는 배포 탭으로.

## 0. 한 줄 요약

**병사는 병종마다 한 묶음으로 보유한다** (보병 10,500명). 플레이어는 **계급**(계정 레벨)이 오를수록 이끄는 규모가 커진다: 처음엔 **부대 하나만 이끄는 초급 지휘관**, 오를수록 ① 출진하는 군단 수, ② 군단 하나에 넣는 병종 가지 수, ③ 병종마다 보유할 수 있는 최대 병력이 늘어난다. 전투에 들어갈 때 군단 병력은 **진형 칸 6개에 자동으로 나눠** 서므로, 한 병종만 넣어도 진형 모양이 생긴다.

## 1. 지금 → 바뀌는 것

| | 지금 | 바뀜 |
|---|---|---|
| 보유 단위 | 부대(UnitState) 여러 개, 같은 병종도 여러 개 | **병종 묶음** 하나씩 (병종마다 1개) |
| 부대 관리 화면 | 부대 13개 카드 | 병종 카드 (보병·창병·궁병·기병·첨병 + 승급 병종), 승급 병종은 들여쓴 나무. **배포 탭 줄** |
| 출진 규모 | 처음부터 군단 3개 × 칸 4~5개 | **계급**으로: 처음 군단 1개 × 병종 1가지 |
| 군단 편성 | 장수 + 칸 6개, 칸마다 보유 부대 1개 | 장수 + **병종 칸 n개**, 칸마다 (병종, 인원) |
| 진형 | 칸 6개에 넣은 부대의 자리 | 군단 병력을 진형 칸 6개에 **자동 배치** (병종 1개여도 6칸) |
| 보유 상한 | 부대 하나 5,000 × 부대 수 20 | **병종마다** 최대 병력 (계급으로) |
| 새 병사 | 훈련도·결속을 바꾸지 않음 | 새 병사는 계급에 따른 **기본 훈련도·결속**(50 → 최대 90)으로 들어와 기존 병력과 평균 |
| 승급 | 부대에서 인원을 갈라 승급 부대로 (R-52 v1.59) | 같은 생각 그대로: **병종 묶음 → 승급 병종 묶음**으로 인원 옮기기 |

## 2. 계급 (계정 레벨, 새로)

지금은 계정 레벨이 없다 (장수 레벨만 있음). 새로 둔다.

| 항목 | 결정 |
|---|---|
| 레벨 | 계정마다 1부터. 최대 30 (예시) |
| 화면 | 레벨 대신 **계급 이름**으로 보인다 (예: "백부장"). 옆 작은 ⓘ → 말풍선: 지금 계급·레벨, 출진 군단 수, 군단당 병종 칸 수, 병종 최대 병력, 새 병사 기본 훈련도·결속, **다음 계급과 그때 늘어나는 것** |
| 경험치 | **나중에 정한다** (사용자 결정). 지금은 경험치 없이 레벨만 |
| 테스트 | **마스터 탭에 [계급 −] [계급 +]** (개발 행동 `dev.lordLevel`, Count = 바꿀 양, 1~30 안으로). 이것으로 레벨을 바꿔 편성을 시험한다 |

### 2.1 계급 이름 (추천)

세계관이 고대 전쟁이라 근대 군대 이름(소대장·중대장·대대장)보다 **옛 군대 이름**을 추천한다. 한자 없이 한글로만 쓴다 (01 타이틀에서 한자 낙관을 뺀 것과 같은 방향).

| 추천 (옛 군대) | 뜻 | 근대식으로 치면 |
|---|---|---|
| **십부장** | 병사 열 명의 우두머리 | 분대장 |
| **백부장** | 백 명 | 소대장 |
| **천부장** | 천 명 | 중대장·대대장 |
| **교위** | 한 부(部)를 맡는 무관 | 연대장 |
| **장군** | 군 하나 | 사단장 |
| **대장군** | 모든 군 | 군단장·총사령관 |

- 다른 안: 근대식 그대로 (소대장 → 중대장 → 대대장 → 연대장 → 사단장 → 군단장). 뜻이 바로 통하지만 세계관과 덜 맞는다.
- 이름은 문구(`rank.<id>`)라 나중에 바꾸기 쉽다.

### 2.2 계급표 (예시, `campaign.json` ranks)

| 레벨 | 계급 | 출진 군단 수 | 군단당 병종 칸 | 병종마다 최대 병력 | 새 병사 훈련도·결속 |
|---|---|---|---|---|---|
| 1 | 십부장 | **1** | **1** | 3,000 | 50 |
| 3 | 백부장 | 1 | 2 | 5,000 | 54 |
| 6 | 천부장 | 2 | 2 | 8,000 | 60 |
| 10 | 교위 | 2 | 3 | 12,000 | 68 |
| 15 | 장군 | 3 | 3 | 16,000 | 78 |
| 21 | 대장군 | 3 | 4 | 20,000 | **90** (최대) |

- 계급은 레벨 구간: 레벨이 그 계급의 시작 레벨 이상이면 그 계급. 칸·군단 수·최대 병력은 계급 단위로 늘어난다.
- **새 병사 기본값만 레벨마다 조금씩**: 기본 = min(90, 50 + 2 × (레벨 − 1)) → Lv1 50, Lv5 58, Lv10 68, Lv21 이상 90 (사용자 결정: 50에서 시작해 레벨마다 조금씩, 최대 90).
- 군단당 병종 칸 최대는 진형 칸 수(6)보다 작게.
- 장수 통솔 한도(군단 병력 5,000~20,000, `balance.json troopCap`)는 **그대로**. 실제 군단 병력 = min(통솔 한도, 넣은 인원 합).
- **표의 숫자는 마스터 [계급 ±]로 직접 해 보고 고친다.**

## 3. 병종 묶음 (보유)

| 값 | 내용 |
|---|---|
| 병종 | 묶음마다 하나 (보병, 방패병 …). 같은 병종 묶음은 2개가 될 수 없다 |
| 병력·부상병 | 지금 부대와 같음 (부상병 자연 회복 R-61, 치료 그대로) |
| 훈련도·결속 | **묶음마다 하나**. 0~100 (화면 %). 전투 보정은 지금과 같음 |
| 최대 병력 | 병력 + 부상병 ≤ 계급표의 병종 최대 병력. 승급 병종도 각자 같은 상한 |
| 위 병종 | 승급 병종 묶음은 위 병종을 표시용으로 안다 (나무 그리기) |

### 3.1 새 병사가 들어올 때 (사용자 결정)

- **징병·모병**으로 들어오는 새 병사의 훈련도·결속 = 계급표의 **새 병사 기본값** (Lv1 50 … 최대 90).
- 묶음 값 = (기존 병력 × 기존 값 + 새 병사 × 기본값) ÷ (기존 + 새), 내림.
  - 예: 보병 2,000명 훈련도 80에 Lv1(기본 50)로 500명 징병 → (2,000×80 + 500×50) ÷ 2,500 = **74**.
  - 예: 훈련도가 기본값보다 낮은 묶음(예 30)은 새 병사가 들어오면 **오른다**.
- **치료**(부상병 → 병력)는 원래 그 묶음 병사라 값을 바꾸지 않는다. 자연 회복도 같다.
- **승급**으로 들어오는 병사는 원래 묶음의 값을 가지고 와서 평균 (R-52 합치기와 같음).
- 훈련(돈 → 훈련도 +10)은 지금처럼.

### 3.2 승급·충원

- **승급** (R-52 그대로 생각): 보병 묶음에서 N명을 빼 방패병 묶음으로. 비용 ⌈N/1000⌉ × 금액, 방패병 쪽 훈련도·결속은 가중 평균, 방패병 상한을 넘으면 안 됨. 기본 병종 묶음은 0이 되어도 남는다.
- **충원**: 징병(군량)·모병(돈)·치료는 묶음 단위. 부대 관리의 [충원 +500] 그대로.
- **새 부대 창설·해산은 없어진다** (병종 묶음은 처음부터 다 있음, 0명일 수 있음).

## 4. 군단 편성

```
출진 = 군단 m개 (m = 계급표 출진 군단 수)
군단 = 장수 1명 + 진형 + 역할 + 병종 칸 n개 (n = 계급표)
병종 칸 = (병종, 인원)   예: (보병, 2,000) (궁병, 1,000)
```

| 규칙 | 초안 |
|---|---|
| 군단 수 | 계급표의 수까지 (처음 1). 장수는 여럿 보유해도 출진은 그 수만 |
| 칸 수 | 계급표의 수까지 (처음 1). 빈 칸 허용 (최소 1칸은 차야 출진) |
| 한 군단 안 같은 병종 | 두 칸에 같은 병종 금지 (같은 병종이면 인원을 한 칸에 모은다) |
| 여러 군단이 같은 병종 | 된다. 단 모든 군단에 넣은 그 병종 인원 합 ≤ 그 병종의 출전 가능 병력 (부상병 제외) |
| 군단 병력 | 칸 인원 합 ≤ 장수 통솔 한도 |
| 상황별 편성 | 지금처럼 (기본·야전·성새전·수상전) |
| 병력이 줄었을 때 | 편성에 적힌 인원보다 보유가 적으면 출진 때 **비율대로 줄여** 넣는다 (화면에 경고) |
| 계급이 내려갈 때 (마스터 [계급 −]) | 넘치는 군단·칸은 출진 때 뒤에서부터 빼고 편성 화면에 표시 (편성 자체는 지우지 않음) |

## 5. 전투 배치 — 진형 칸 6개에 자동으로 나누기

전투 쪽 "소부대 6개 + 진형 자리" 모델은 그대로 두고, **출진할 때** 군단의 병종 칸을 진형 칸 6개로 나눈다 (전투 코드는 거의 그대로).

1. 병종을 근접·원거리로 나눈다 (`troopTypes.json` 태그 `ranged` = 원거리, 그 밖 근접).
2. 칸 배정 (진형 칸 이름: 선봉·중군·좌익·우익·좌비·우비):
   - 근접만 있으면 6칸 모두 근접, 원거리만 있으면 6칸 모두 원거리.
   - 둘 다 있으면 **근접 = 선봉·좌익·우익·중군, 원거리 = 좌비·우비**.
   - 근접(또는 원거리) 병종이 여럿이면 그 칸들을 인원 비율로 나눠 갖는다 (칸 순서대로, 큰 병종부터).
3. 각 칸 인원 = 그 병종 인원 ÷ 그 병종이 받은 칸 수 (나머지는 앞 칸부터 1명씩).
4. 칸마다 그 병종 묶음의 훈련도·결속을 쓴다.
5. 전투가 끝나면 칸들의 사망·부상을 **병종 묶음으로 모아** 돌려준다.

→ 병종 1개짜리 단독 군단도 어린진이면 어린 모양, 학익진이면 학익 모양으로 6개 덩어리가 선다. 진형 특성치(R-72)·상성은 지금처럼.

- 칸 배정은 **자동만** (확정). 나중에 "이 병종은 앞/뒤"를 고르게 할 수 있다.
- 첨병·공성 병기(투석기)·공병: 원거리·근접 규칙에 그대로. 투석기는 원거리(뒤 칸).

## 6. 고용 (hiring.md 2.2)

- 지금: 부대를 통째로 등록 → **병종 묶음에서 n명을 떼어 등록** (등록한 인원은 그동안 내 편성에 못 씀). 훈련도·결속은 등록 순간 값.
- 고용 부대는 출진 준비에서 군단에 넣는다. **계급의 병종 칸 수에 들지 않는다** (진형 칸 6개까지) — 십부장도 고용할 수 있게 (2026-11-14 구현 때 데스크탑 결정, **사용자 확인 필요**).

## 7. 세이브 바꾸기 (예전 세이브 → 새 세이브)

- 부대들을 병종별로 합친다: 병력·부상병은 더하고, 훈련도·결속은 인원 가중 평균. 승급으로 갈라진 부대(ParentUnitId)도 병종별로 합친다.
- 합친 결과가 그 병종 최대 병력을 넘으면 **그대로 두고**(넘친 상태 허용) 충원만 막는다.
- 계급은 1부터 (경험치 정책이 생기면 그때 지난 진행으로 다시 계산).
- 편성: 첫 번째 군단의 가장 큰 병종 하나만 남긴다 (계급 1 = 군단 1·칸 1). 나머지는 지우지 않고 계급이 오르면 쓸 수 있게 둔다.

## 8. 처음 지급 (새 게임) — 예시

| 항목 | 지금 | 바뀜 |
|---|---|---|
| 병사 | 부대 13개 (합 38,500) | 보병 3,000 · 창병 2,000 · 궁병 2,000 · 기병 1,000 · 첨병 500 (십부장 상한 3,000) |
| 장수 | 3명 | 3명 그대로 (출진은 1명, 고르는 재미) (확정) |

- **큰 영향**: 처음 전투가 "한 장수 + 한 병종"이 된다 (사용자 결정: 단조로워도 처음은 부대 하나). 스텝 01~05 적 편성과 승률(StepBalanceTests), 처음 안내·스토리 문구, 기준 전투 일부를 다시 맞춰야 한다. 스텝마다 "그때의 예상 계급"을 정해 적 규모를 맞춘다.
