# 치장 (병사 겉모습 꾸미기)

> 상태: **기획 초안 (2026-11-15)**, 구현 전 · 미결은 9장 (1번 결제 전용 허용 · 2번 보석 · 결제만은 확정)
> 관련: 상점 원칙 [economy.md](economy.md) 0장 · 병종 [troops.md](troops.md) · 병사 모양 [../../impl/unity/art.md](../../impl/unity/art.md) 1장 (`SoldierMeshes`, `tools/troop_pictures.js`) · 녹화 [replay.md](replay.md) · 용병 [hiring-v2.md](hiring-v2.md) · 대전 [pvp.md](pvp.md)

## 0. 원칙

- **치장은 겉모습만 바꾼다.** 능력치·전투 계산·AI 판단에 들어가지 않는다. 전투 결과와 상태 해시(재현 검사)는 치장이 있든 없든 같다.
- **팀 구분은 해치지 않는다.** 몸통의 팀 색(아군 파랑 · 적 빨강 …)은 치장이 덮지 않는다. 치장은 투구 · 덧옷 테두리 · 망토 · 방패 무늬처럼 팀 색 **바깥 부위**만 바꾼다.
- **규칙 코드는 치장을 모른다.** 규칙은 "이 병종에 이 치장 id들이 입혀져 있다"는 정보만 전달하고, 어떻게 그릴지는 화면(그림)이 정한다. 테마를 바꾸면 같은 치장 id가 다른 그림이 된다 ([../theme.md](../theme.md)).
- 새 치장은 **데이터 추가**로만 늘린다 (코드 수정 없이). 새 **부위**를 추가할 때만 그림 코드에 부위 하나를 등록한다.

## 1. 범위 (단계)

| 단계 | 대상 | 내용 |
|---|---|---|
| **1단계** | **병종 치장** | 병종(1단계 계열: 보병 · 창병 · 궁병 · 기병 · 정찰병 · 공병)마다 부위별로 하나씩. 그 계열의 모든 병사가 입는다. 승급한 병종(2·3단계)도 계열의 치장을 그대로 입는다 |
| 2단계 (나중) | 장수 치장 | 장수 인형(망토 · 투구 장식 · 말 마구)과 초상 테두리 |
| 3단계 (나중) | 깃발 · 전장 효과 | 군기 무늬, 승리 연출 |

- 1단계를 계열 단위로 잡는 까닭: 병사 수가 많아(화면에 약 2,000명) 병사 하나하나가 아니라 **무리 전체가 바뀌어야** 눈에 띄고, 그리기도 병종 · 색마다 한 묶음(GPU 인스턴싱)이라 계열 단위가 맞다.

## 2. 부위

| 부위 id | 이름 (문구 키) | 바꾸는 것 | 쓰는 계열 |
|---|---|---|---|
| `helmet` | 투구 | 투구 모양 · 색 (기본: 짙은 갈색 챙) | 모두 (정찰병은 머리띠 → 두건 · 머리띠 색) |
| `trim` | 덧옷 | 몸통 가장자리 · 어깨 덧댐 · 허리띠 색 (팀 색 몸통은 그대로) | 모두 |
| `cape` | 망토 | 등 뒤 짧은 망토 (기본: 없음) | 보병 · 창병 · 기병 |
| `shield` | 방패 무늬 | 방패 테 · 가운데 무늬 | 보병 |
| `weapon` | 무기 | 창날 · 칼 · 활 색과 모양 (길이는 그대로, 병종 구분이 흐려지지 않게) | 모두 |
| `mount` | 마구 | 말 안장 덮개 · 고삐 색 | 기병 |

- 부위 목록은 데이터 (`cosmetics.json`의 `slots`). 기본값(아무것도 안 입음)은 지금 모습.

## 3. 데이터 (`data/Rules/cosmetics.json`, 예시)

```json
{
  "slots": [
    { "id": "helmet", "nameKey": "cos.slot.helmet" },
    { "id": "trim",   "nameKey": "cos.slot.trim" },
    { "id": "cape",   "nameKey": "cos.slot.cape", "lines": ["infantry", "spearman", "cavalry"] },
    { "id": "shield", "nameKey": "cos.slot.shield", "lines": ["infantry"] },
    { "id": "weapon", "nameKey": "cos.slot.weapon" },
    { "id": "mount",  "nameKey": "cos.slot.mount", "lines": ["cavalry"] }
  ],
  "items": [
    {
      "id": "helmet_iron",
      "slot": "helmet",
      "nameKey": "cos.helmet_iron",
      "look": { "shape": "tall", "color": "iron" },
      "lines": null,
      "obtain": { "shop": { "gem": 120 }, "playPaths": ["story:step05"] }
    },
    {
      "id": "cape_crimson",
      "slot": "cape",
      "nameKey": "cos.cape_crimson",
      "look": { "shape": "short", "color": "crimson" },
      "obtain": { "shop": { "priceKRW": 2500 } }
    }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `slot` | 부위 id (2장) |
| `lines` | 입을 수 있는 계열 (null = 그 부위를 쓰는 모든 계열) |
| `look` | 그림에 넘기는 값 (모양 · 색 이름). **규칙은 읽지 않는다**, 그림 쪽이 테마의 색 · 모양 표로 바꾼다 |
| `obtain.shop` | 상점 가격: `gem`(보석) · `priceKRW`(결제) 중 하나 (돈은 쓰지 않음, 9장 2) |
| `obtain.playPaths` | 플레이로 얻는 길 (스토리 스텝 보상 · 숨은 보상 · 이벤트). 없으면 상점 전용 (허용, 9장 1) — 단 부위마다 이 칸이 있는 치장이 하나 이상 |

- 색 이름 → 실제 색은 테마 파일 (`data/Themes/<테마>/cosmetics.look.json`, 예: `iron` = 쇠 회색, `crimson` = 진홍). 문구는 `cos.*` 키.
- 검사(데이터 검사 테스트): 부위 id가 있는지, `lines`가 부위의 계열 안인지, 가격이 하나뿐인지, 문구 키가 있는지, **부위마다 `playPaths`가 있는 치장이 하나 이상**인지 (9장 1).

## 4. 세이브

```
CampaignState
  OwnedCosmetics: List<string>                              // 가진 치장 id
  EquippedCosmetics: Dictionary<string, Dictionary<string,string>>  // 계열 id → (부위 id → 치장 id)
```

- 예전 세이브는 둘 다 빈 것 = 지금 모습.
- 입히기 검사: 가진 것만, 그 계열 · 부위에 맞는 것만. 벗기면 그 부위 항목을 지운다.
- 서버 동기화 · 클라우드 세이브에 그대로 실린다 (다른 기기에서도 같은 모습).

## 5. 얻기

| 길 | 내용 |
|---|---|
| 상점 [치장] 묶음 | 보석 · 결제 (9장 2). 결제는 기존 영수증 검증 흐름 그대로 (R-64, 행동 `store.purchase`) |
| 스토리 보상 | 특정 스텝 첫 클리어 보상에 치장 id (스텝 데이터 `rewards`에 `cosmetic` 종류 추가) |
| 숨은 보상 | [secrets.md](secrets.md)의 보상 종류에 치장 추가 (도감에도 보임) |
| 이벤트 · 시즌 | 나중 (기간 한정) |

- 이미 가진 치장이 또 나오면(보상 중복) 대신 돈 n (수치 미정).

## 7. 전투 · 녹화 · 남의 군대에 보이기

- 출진 때 군단 설정(`BattleSetup`의 군단)에 **보이기 정보** `Looks`(계열 → 부위 → 치장 id)를 싣는다. 규칙 계산은 이 칸을 읽지 않고, **상태 해시에도 넣지 않는다** (같은 전투면 치장과 관계없이 같은 해시).
- 녹화(R-54)는 설정을 그대로 저장하므로 다시 보기에도 그때 모습이 나온다. 그 뒤 치장을 바꿔도 녹화는 그대로.
- 용병(빌린 부대, [hiring-v2.md](hiring-v2.md)) · 대전 상대([pvp.md](pvp.md)) · 영토 공성전 상대는 등록 · 대전 자료에 주인의 `Looks`를 함께 보낸다 (서버는 그대로 전달만).
- AI 적(스토리)은 스텝 데이터에 `looks`를 둘 수 있다 (적장 군단의 특색, 선택).
- 그림 쪽: `SoldierMeshes.For(계열, looks)` — 부위마다 기본 도형을 바꾸거나 더하고, 색은 하위 메시(재질) 하나 더(치장 색). 같은 계열 · 같은 looks · 같은 팀 색이면 한 묶음이라 그리기 수는 "다른 모습의 수"만큼만 는다. 병종 그림은 `tools/troop_pictures.js`처럼 화면에서 같은 규칙으로 그린다 (런타임 그리기로 바꿀지는 미결 4).

## 8. 검증 (구현할 때 verification.md에 R 번호로)

| 제안 | 내용 |
|---|---|
| R-치장-1 | 치장을 입힌 전투와 안 입힌 전투(같은 시드 · 명령)의 결과와 상태 해시가 같다 |
| R-치장-2 | 입히기 검사: 안 가진 것 · 다른 계열 · 다른 부위는 받지 않는다. 벗기면 기본 |
| R-치장-3 | 얻기: 상점 구매(가짜 영수증 포함) · 스텝 보상 · 숨은 보상으로 `OwnedCosmetics`에 들어가고, 중복이면 돈으로 바뀐다 |
| R-치장-4 | 녹화 · 용병 · 대전 상대 설정의 `Looks`가 그대로 전달된다 (서버 왕복 포함) |
| 데이터 검사 | 3장 끝의 검사 |
