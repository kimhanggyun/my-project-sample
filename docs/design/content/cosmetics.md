# 치장 (병사 겉모습 꾸미기)

> 상태: **1단계 구현 (2026-11-15, R-108)**: 데이터 · 세이브 · 사기/입히기 행동 · 전투 설정 겉모습(해시 제외) · 병사 인형 갑옷/말 색 · 병종 그림 런타임 렌더 · 꾸미기 화면(병력 카드 [꾸미기]). **2단계 규칙·서버 (2026-11-15, 원격, R-111)**: 스텝 첫 클리어 보상 `rewards.cosmetics` · 숨은 보상 `reward.cosmetic` (이미 가졌으면 엽전 `duplicateGold`), 치장 상품 `products.json` kind cosmetic(결제 전용 허용, R-30 예외) · 영수증 → 치장, 용병 부대 등록 · 영토 수비 스냅샷에 주인의 갑옷 · 말 → 출진 설정. 아직: 상점 [치장] 묶음 화면 · 꾸미기 시안 · 대전(PvP)은 대전 자체가 아직 없음 (붙일 때 수비 스냅샷과 같은 DefenseUnit.Armor · Horse를 쓴다) · 미결은 9장 (1 결제 전용 허용 · 2 보석 · 결제만 · 3 팀 색 자동 조정 · 4 병종 그림 런타임 렌더 · 5 세트 효과 나중 · 6 첫 목록(갈색 갑옷 · 진남색 말, 돈) · 7 단위 = 갑옷 한 벌 + 말 색 따로는 확정)
> 관련: 상점 원칙 [economy.md](economy.md) 0장 · 병종 [troops.md](troops.md) · 병사 모양 [../../impl/unity/art.md](../../impl/unity/art.md) 1장 (`SoldierMeshes`, `tools/troop_pictures.js`) · 녹화 [replay.md](replay.md) · 용병 [hiring-v2.md](hiring-v2.md) · 대전 [pvp.md](pvp.md)

## 0. 원칙

- **치장은 겉모습만 바꾼다.** 능력치·전투 계산·AI 판단에 들어가지 않는다. 전투 결과와 상태 해시(재현 검사)는 치장이 있든 없든 같다.
- **팀 구분은 해치지 않는다.** 몸통의 팀 색(아군 파랑 · 적 빨강 …)은 갑옷이 덮지 않는다. 갑옷은 투구 · 덧옷 테두리 · 망토 · 방패 무늬 · 무기 색처럼 팀 색 **바깥 부분**만 바꾼다. 갑옷 색이 전투의 어느 팀 색과 비슷하면 전장에서는 **자동으로 채도를 낮추고 어둡게** 그린다 (9장 3).
- **규칙 코드는 치장을 모른다.** 규칙은 "이 계열이 이 갑옷을 입었다"는 id만 전달하고, 어떻게 그릴지는 화면(그림)이 정한다. 테마를 바꾸면 같은 갑옷 id가 다른 그림이 된다 ([../theme.md](../theme.md)).
- 새 갑옷은 **데이터 추가**로만 늘린다 (코드 수정 없이). 갑옷이 쓰는 새 **모양 요소**(예: 새 투구 모양)를 더할 때만 그림 코드에 하나 등록한다.

## 1. 범위 (단계)

| 단계 | 대상 | 내용 |
|---|---|---|
| **1단계** | **병종 갑옷** | 병종(1단계 계열: 보병 · 창병 · 궁병 · 기병 · 정찰병 · 공병)마다 **갑옷 한 벌**을 입힌다. 그 계열의 모든 병사가 입는다. 승급한 병종(2·3단계)도 계열의 갑옷을 그대로 입는다 |
| 2단계 (나중) | 장수 치장 | 장수 인형(망토 · 투구 장식 · 말 마구)과 초상 테두리 |
| 3단계 (나중) | 부위별 꾸미기 · 깃발 | 갑옷을 부위(투구 · 망토 …)로 나눠 섞어 입기, 군기 무늬, 승리 연출 |

- **단위 = 갑옷 한 벌 (2026-11-15 사용자)**: 부위마다 고르면 처음엔 너무 복잡하다. 한 벌을 고르면 투구 · 덧옷 · 망토 · 방패 · 무기 색이 함께 바뀐다. 고르는 칸 하나, 상점 상품 하나, 미리보기 한 장이라 화면 · 데이터 · 그림이 모두 단순하다. 부위별 섞어 입기는 3단계.
- 계열 단위로 잡는 까닭: 병사 수가 많아(화면에 약 2,000명) 병사 하나하나가 아니라 **무리 전체가 바뀌어야** 눈에 띄고, 그리기도 병종 · 색마다 한 묶음(GPU 인스턴싱)이라 계열 단위가 맞다.

## 2. 갑옷 한 벌이 바꾸는 것

| 요소 | 바꾸는 것 | 기본 (안 입음 = 지금 모습) |
|---|---|---|
| 투구 | 모양(뾰족 · 높은 · 깃털 · 두건) · 색 | 짙은 갈색 뾰족 투구 (정찰병은 팀 색 머리띠) |
| 덧옷 | 몸통 가장자리 · 어깨 덧댐 · 허리띠 색 (팀 색 몸통은 그대로) | 갈색 허리띠만 |
| 망토 | 등 뒤 짧은 망토 있음/없음 · 색 | 없음 |
| 방패 | 방패 테 · 가운데 무늬 (보병) | 나무 방패 |
| 무기 | 창날 · 칼 · 활 색 (길이 · 모양은 그대로, 병종 구분이 흐려지지 않게) | 쇠 · 나무 |
| 마구 | 말 안장 덮개 · 고삐 색 (기병) | 팀 색 안장 덮개 |

- 갑옷 데이터가 요소마다 값을 정한다. 그 계열에 없는 요소(궁병의 방패 등)는 무시한다.

### 2.1 말 색 (갑옷과 따로, 2026-11-15 사용자)

- 기병의 **말 몸 색**은 갑옷과 따로 고른다 (`kind: horse`). 기본 = 갈색 (지금 모습). 말을 탄 계열(기병)에만 쓴다.
- 장수의 말(흰 말)은 2단계(장수 치장)에서.

### 2.2 첫 목록 (1단계 출시, 2026-11-15 사용자 확정)

| 종류 | id | 모습 | 얻기 |
|---|---|---|---|
| 갑옷 | (기본) | **지금 모습** (모든 계열 공통) | 처음부터 |
| 갑옷 | `armor_brown` | **갈색 가죽 갑옷**: 투구 · 어깨 덧댐 · 덧옷 테두리 · 허리띠가 갈색 가죽. 몸통 팀 색은 그대로 (0장) | **돈**으로 구매 (모든 유저) |
| 말 | (기본) | **갈색 말** (지금 모습) | 처음부터 |
| 말 | `horse_navy` | **진남색 말** | **돈**으로 구매 (모든 유저) |

- 가격(돈 = 엽전)은 임시값, 테스트 뒤 정한다 ([../open-values.md](../open-values.md)).
- **다음 목록 (2026-11-15 사용자, 구매 정책 [economy.md](economy.md) 0장)**: 선호 색 갑옷 · 말 (검정 · 흰)은 **금괴**로. 겉모습만 (방어 · 이동 보정은 "나중에 고민", 넣게 되면 치장이 아닌 장비 체계로 따로). 특별 갑옷 · 말(결제 전용)도 같음.

## 3. 데이터 (`data/Rules/cosmetics.json`, 예시)

```json
{
  "items": [
    {
      "id": "armor_brown",
      "kind": "armor",
      "nameKey": "cos.armor_brown",
      "lines": null,
      "look": { "helmet": "pointed:leather", "trim": "leather", "shield": "rim:leather" },
      "obtain": { "shop": { "gold": 3000 } }
    },
    {
      "id": "horse_navy",
      "kind": "horse",
      "nameKey": "cos.horse_navy",
      "lines": ["cavalry"],
      "look": { "horse": "navy" },
      "obtain": { "shop": { "gold": 3000 } }
    }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `kind` | `armor`(갑옷 한 벌) · `horse`(말 색, 2.1) |
| `lines` | 입을 수 있는 계열 (null = 모든 계열) |
| `look` | 그림에 넘기는 값 (요소 → "모양:색" 이름). **규칙은 읽지 않는다**, 그림 쪽이 테마의 색 · 모양 표로 바꾼다. 빠진 요소는 기본 |
| `obtain.shop` | 상점 가격: `gold`(돈, 모든 유저) · `gem`(보석, 결제 위주) · `priceKRW`(결제) 중 하나 (9장 2) |
| `obtain.playPaths` | 플레이로 얻는 길 (스토리 스텝 보상 · 숨은 보상 · 이벤트). **돈 가격이면 플레이로 얻는 것으로 친다** (돈은 보상으로 번다). 돈 가격도 이 칸도 없으면 결제 전용 (허용, 9장 1) — 단 **모든 계열이 입을 수 있는(`lines` null) 갑옷 중 플레이로 얻을 수 있는 것이 하나 이상** |

- 색 · 모양 이름 → 실제 그림은 테마 파일 (`data/Themes/<테마>/cosmetics.look.json`, 예: `iron` = 쇠 회색, `crimson` = 진홍, `tall` = 높은 투구). 문구는 `cos.*` 키.
- 검사(데이터 검사 테스트): `lines`가 실제 1단계 계열인지, 가격이 하나뿐인지, `look`의 요소 · 이름이 테마 표에 있는지, 문구 키가 있는지, **플레이로 얻는 공용 갑옷이 하나 이상**인지 (9장 1).

## 4. 세이브

```
CampaignState
  OwnedCosmetics: List<string>               // 가진 갑옷 · 말 색 id
  EquippedArmor: Dictionary<string, string>  // 계열 id → 갑옷 id
  EquippedHorse: Dictionary<string, string>  // 계열 id(말 탄 계열) → 말 색 id
```

- 예전 세이브는 둘 다 빈 것 = 지금 모습.
- 입히기 검사: 가진 것만, 그 계열이 입을 수 있는 것만. 벗기면 그 계열 항목을 지운다.
- 하나를 사면 그 갑옷을 입을 수 있는 **모든 계열**에 입힐 수 있다 (계열마다 따로 사지 않음).
- 서버 동기화 · 클라우드 세이브에 그대로 실린다 (다른 기기에서도 같은 모습).

## 5. 얻기

| 길 | 내용 |
|---|---|
| 상점 [치장] 묶음 | 돈(모든 유저) · 보석 · 결제 (9장 2). 첫 목록은 돈 (2.2). 결제는 기존 영수증 검증 흐름 그대로 (R-64, 행동 `store.purchase`) |
| 스토리 보상 | 특정 스텝 첫 클리어 보상에 갑옷 id (스텝 데이터 `rewards`에 `cosmetic` 종류 추가) |
| 숨은 보상 | [secrets.md](secrets.md)의 보상 종류에 갑옷 추가 (도감에도 보임) |
| 이벤트 · 시즌 | 나중 (기간 한정) |

- 이미 가진 갑옷이 또 나오면(보상 중복) 대신 돈 n (수치 미정 → **임시 엽전 200**, `cosmetics.json` `duplicateGold`). 결제 치장을 이미 가졌을 때도 같다.
- **구현 (2026-11-15, R-111)**:
  - 스텝 데이터 `rewards.cosmetics: [치장 id]`, 숨은 보상 `reward.cosmetic: 치장 id`(받는 장수와 상관없이 계정이 얻음).
  - 치장 상품 = `products.json`의 `kind: "cosmetic"` + `cosmeticId` (`priceKRW`, 영수증 검증 R-64 그대로). 편의 기능처럼 플레이 경로 없이 팔 수 있다 (R-30 예외).
  - 데이터 검사: 치장의 `playPaths`(`story:스텝` · `secret:id`)가 실제 보상과 맞는지, 결제 치장(`priceKRW`)에 치장 상품이 있는지 (`CosmeticService.ValidateRewards`).
  - 예시 데이터 (임시): step06 첫 클리어 = 무쇠 갑옷(`armor_iron`), '들판의 철벽' = 진홍 갑옷(`armor_crimson`), 결제 = 황금 갑옷(`armor_gold`, 3,300원).

## 7. 전투 · 녹화 · 남의 군대에 보이기

- 출진 때 군단 설정(`BattleSetup`의 군단)에 **보이기 정보** `Armors`(계열 → 갑옷 id)를 싣는다. 규칙 계산은 이 칸을 읽지 않고, **상태 해시에도 넣지 않는다** (같은 전투면 갑옷과 관계없이 같은 해시).
- 녹화(R-54)는 설정을 그대로 저장하므로 다시 보기에도 그때 모습이 나온다. 그 뒤 갑옷을 바꿔도 녹화는 그대로.
- 용병(빌린 부대, [hiring-v2.md](hiring-v2.md)) · 대전 상대([pvp.md](pvp.md)) · 영토 공성전 상대는 등록 · 대전 자료에 주인의 `Armors`를 함께 보낸다 (서버는 그대로 전달만).
  - **구현 (2026-11-15, R-111)**: 용병 부대 등록 `HireListing.Armor` · `Horse` (그 병종 계열에 주인이 입힌 것) → 고용 해석 `HiredForces.Looks` → 출진 설정 `UnitSetup.Armor` · `Horse`. 영토 수비 스냅샷 `DefenseUnit.Armor` · `Horse` → 공성전 적 `UnitSetup`. 예전 등록 · 스냅샷은 null = 기본 모습. 대전(PvP)은 아직 없다.
- AI 적(스토리)은 스텝 데이터에 `armors`를 둘 수 있다 (적장 군단의 특색, 선택).
- 그림 쪽: `SoldierMeshes.For(계열, 갑옷)` — 요소마다 기본 도형을 바꾸거나 더하고, 색은 하위 메시(재질) 하나 더(갑옷 색, 팀 색과 가까우면 자동 조정 — 9장 3). 같은 계열 · 같은 갑옷 · 같은 팀 색이면 한 묶음이라 그리기 수는 "다른 모습의 수"만큼만 는다. 병종 그림은 같은 인형을 게임 안에서 찍어 만든다 (런타임 렌더, 9장 4).

## 11. 병사 겉모습: 세트 = 전체 색 · 등급별 모양 (R-149, 2026-11-24 사용자)

- **세트 하나가 병사 전체 색**: 몸통(body) · 다리(legs) · 모자(hat) · 방패(shield) · 장식(trim: 테 · 무늬 · 꼭지 · 어깨) · 깃(plume). 예전엔 투구 꼭지 · 어깨 · 방패만 갑옷 색이고 몸통 · 모자는 편 색이었음. 아군 · 적 구분은 바닥 원 · 이름표로 충분 (사용자: 전술 전투라 겹쳐도 됨).
- **look 값** = "모양:색" · "모양" · "색" (색 이름은 테마 그림 `CosmeticLooks`). 모자 kasa 삿갓형 · helmet 둥근 투구 · plume 깃 투구 / 방패 round · square · tower(긴 네모) / 무늬 pattern none · rim 테 · cross 십자 · boss 큰 꼭지.
- **등급별 모양**: 엽전 · 플레이 세트 = 삿갓형, 금괴 세트 = 투구, 결제 세트 = 깃 투구. 상위 세트 방패 = 네모 · 테 · 십자.
- **병종 기본 모양** (`cosmetics.json` troopLooks): 방패병 = 긴 네모 방패, 근위병 = 긴 네모 + 테 + 투구, 장창병 · 쇠뇌병 · 중기병 = 투구, 철기 = 깃 투구. 세트가 색 · 무늬를 덮어쓰되, **방패 모양은 병종 것**(방패병 → 긴 네모)을 지키고 **모자는 병종 · 세트 중 높은 등급**(삿갓 < 투구 < 깃 투구).
- **그리기**: `SoldierLook` (병종 기본 + 세트 + 말 색) → `SoldierMeshes.For(…, shape)` (모자 · 방패 · 장식 · 깃 부위). 샘플전투2 우리 편 · 꾸미기 미리보기(`TroopPictureRenderer`)가 씀. 옛 전투는 예전 모습 그대로.
- **[꾸미기] 탭 (개발용, 개발 줄 [테스트] 바로 뒤)**: 병종을 고르고 세트 · 말 색을 사지 않고 입혀 봄 (`DevLooks`, 이 기기에만 저장). 샘플전투2 우리 편이 그 모습. 실제 게임에선 병과 · 세트를 사면 자동으로 입음 (나중, 상점 연결).

> 11장의 모자 · 방패 모양 이름 · troopLooks는 12장 부품으로 바뀜 (옛 이름은 세트 look에서 그대로 받음).

## 12. 겉모습 부품 (R-150, 2026-11-24 사용자 "부품마다 그럴듯하게 · 번호로 지움 · 장수 · 말도")

- **부품** = `data/Ui/lookParts.json`, 번호 첫 글자가 부위 (H 투구 · A 갑옷 · C 등 · S 칼·도끼 · P 창 · B 활 · D 방패 · M 말 갖춤), 무기 묶음 L. 만드는 법 · 크기 · 자리 · 색: [look-parts.md](look-parts.md).
- **등급**: basic 기본 · coin 엽전 · gem 금괴 · cash 결제 · general 장수 전용. 높은 등급은 색이 아니라 **모양**이 다름 (금 테 · 깃 · 술 · 큰 실루엣). 어깨 덧댐은 없앰 → 찰갑 · 판금 · 두정갑 · 망토.
- **차림** = 병종 기본 차림 (lookParts troops) → 갑옷 세트 look (`hat` · `shield` = "번호:색", `armor` · `back` = 번호, 나머지는 색 이름) → 말 색 → 개발용 고르기. 세트의 투구 · 방패 · 갑옷은 병종 것보다 등급이 높을 때만 바뀜, 등은 비었을 때만 (화살통 지킴), 방패는 방패 든 병종만.
- **세트 연결** (첫판): 갈색 = 가죽 조끼 A02 · 가죽 투구 H03 / 무쇠 = 찰갑 A03 · 철 투구 H04 · 쇠테 원방패 D04 / 진홍 = 찰갑 · 철 투구 · 네모 방패 D02 · 짧은 망토 C02 / 흑철 = 판금 A04 · 술 첨주 H06 · 짧은 망토 / 백은 = 두정갑 A05 · 철 투구 · 긴 망토 C03 / 황금(결제) = 금테 찰갑 A08 · 깃 투구 H05 · 호두패 D05 · 긴 망토.
- **장수**: 성향마다 기본 차림 (맹장 = 꿩깃 투구 · 명광개 · 장수 망토 · 사모 · 장수 말갑, 지장 = 깃 투구 · 판금 · 긴 망토 · 칠성검 · 용문 방패 · 장식 마구, 책사 = 윤건 · 비단 도포 · 깃털 부채 · 비단 덮개), 총대장은 등에 군기 C06. 크기는 병사의 1.8배.
- **말** (사용자 "말이 어색, 사람과 말이 떨어짐"): 둥근 몸통 · 가슴 · 엉덩이 · 굽은 목 · 주둥이 머리 · 귀 · 갈기 · 꼬리, 두 마디 다리 + 발굽 (따로 흔듦). 탄 사람은 엉덩이가 안장 위 (0.23), 다리를 옆구리로 벌려 등자에.
- **[병사꾸미기] · [장수꾸미기] 탭** (개발 줄): 병종 · 장수 성향 고르기 → 앞 · 옆 그림 + 번호 요약 → 칸 (세트 · 투구 · 갑옷 · 등 · 무기 묶음 · 칼 · 창 · 활 · 방패 · 말 · 색) 카드에서 골라 입혀 봄 (`DevLooks`, 이 기기에만). [세트로 저장] = 번호 JSON 복사 + Editor.log "꾸미기 세트:" → 데스크탑이 상점 세트로. [처음대로] = 고른 것 지움. 샘플전투2 우리 편 · 우리 장수가 그 모습, 적은 기본 차림.
- 실제 게임: 병과 · 세트를 사면 자동으로 입음 (꾸미기 탭은 개발용만).
- **상품 세트 샘플** (2026-11-25 사용자 사진 20261125_2): 엽전 1000 = 철갑 (H04 철 투구 · A03 찰갑, 보병 S13 장검 · D06 용문 방패, 궁병 B20 흑룡 활 · C10 쌍 화살통, 창병 P20 금룡창), 금괴 300 = 금관갑 (H18 금관 투구 · A20 산문갑, 보병 S20 청룡 대검 · D13 거북등 방패, 궁병 · 창병 같음) × 흰 · 검은 · 황금 · 붉은. 세트 색 = 몸 · 투구 · 망토 · 깃 · 방패, 장식 테 · 다리는 편 색 그대로. 가격은 예시.
- **가진 세트 목록** (2026-11-25 사용자 "산 세트는 갖고 있어 언제든 적용, 여러 개면 목록"): 꾸미기 화면 (군대 탭 병종 카드 [꾸미기]) = 큰 미리보기 + 입은 세트 이름 → [가진 갑옷 세트 (n)] (기본 + 산 것, [입기] · 입음 ✓) → [더 얻을 갑옷 세트] (안 산 것, 얻는 길 · [엽전 n] · [금괴 n] 사고 바로 입기), 기병은 말도 같은 두 칸. 셋씩 한 줄. 산 세트는 벗어도 목록에 남고, 하나 사면 입을 수 있는 모든 계열 목록에 나오며 입히기는 계열마다 따로. 샘플전투2 우리 편은 입은 세트로 그림 (개발용 꾸미기 고르기가 있으면 그게 먼저). 규칙: CosmeticService.OwnedFor · NotOwnedFor (테스트 CosmeticTests.OwnedList).
