## 1. 목적

장수 키우기·부대 키우기의 목적은 **다른 유저가 고용할 만한 장수·부대를 만드는 것**이다.

```
키우기 ──▶ 서버에 등록 ──▶ 다른 유저가 전투 기록을 보고 고용 ──▶ 등록한 유저에게 보상
   ▲                                                              │
   └──────────────────── 보상으로 다시 키우기 ◀─────────────────────┘
```

- 사용자는 장수·부대를 키워서 **서버에 등록**한다.
- 등록된 장수·부대는 **다른 유저가 고용**할 수 있다.
- 고용되면 등록한 유저에게 **보상**이 간다.
- 등록된 장수·부대의 **이력(전투 기록)**은 서버에 쌓이고, 다른 유저가 보고 고용할지 판단한다.

## 2. 고용 종류: 장수 고용 · 부대 고용

**두 가지를 따로 등록하고 따로 고용한다** (확정).

| 종류 | 무엇을 빌리나 | 왜 필요한가 | 키우는 곳 |
|---|---|---|---|
| **장수 고용** | 장수 1명 (능력치·레벨·스킬·특성·진형 숙련) | 고용한 유저의 군단을 이끌 지휘관이 필요할 때 | [장수 키우기](general-growth.md) |
| **부대 고용** | 훈련된 부대 (병종·병력·훈련도) | 고용한 유저에게 **부대원(병력)이 부족**할 때. 특화 병종을 쓰고 싶을 때 | [부대 키우기](troop-growth.md) |

- 부대 키우기는 부대를 **통째로 손발이 맞게 훈련**시키는 것이다. 예: 단순 보병을 훈련시켜 **등갑병 부대**로 만들고, 그 부대를 등록하면 다른 유저가 고용할 수 있다.
- 한 전투에 **다른 유저들의 장수와 부대를 섞어서** 고용할 수 있다. 예: A 유저의 장수 + B 유저의 등갑병 부대 + 내 부대.
- 장수 고용과 부대 고용은 **이력도 따로** 쌓인다.

### 2.1 장수 고용

- 등록 내용: 장수 스냅샷 (레벨, 능력치, 특성, 배운 스킬·진형, 진형 숙련).
- 고용하면 **내 부대(또는 고용한 부대)를 이끈다.** 병력 한도는 그 장수의 통솔로 정해진다 ([battle.md](battle.md) 2.4.4).

### 2.2 부대 고용

- 등록 내용: 부대 스냅샷 (병종, 병력, 훈련도, **결속**, 부대 능력치, 부대가 익힌 진형).
- 등록 단위: 등록자가 가진 그 부대의 **부대원 전부**를 등록한다 (확정). 예: 등갑병 8,000명 전부.
- **고용은 인원을 정해서 일부만** 할 수 있다.
  - 고용할 수 있는 인원은 **고용하는 유저의 군량으로 감당할 수 있는 만큼**이다. 고용한 병사도 전투에서 군량을 먹기 때문이다 (병사 1명 하루 1, 1분 = 1주).
  - 동시에 **넣을 장수의 병력 한도** 안이어야 한다.
  - 예: 등갑병 8,000명이 등록되어 있어도, 내 군량으로 3분 전투에 4,000명만 먹일 수 있으면 최대 4,000명까지 고용.
- 고용 비용 = **병사 1명당 가격 × 고용 인원**.
- 등록자 보상도 **고용된 인원에 비례**한다 (비율은 추후 결정).
- 스냅샷 방식이라 같은 장수·부대를 **여러 유저가 동시에 고용**할 수 있다 (확정). 각자 등록 인원 한도까지 고용하며, 서로의 고용 인원이 차감되지 않는다.
- 고용하면 출진 준비에서 **내 장수의 군단 소부대 칸**에 넣는다 (내 보유 부대와 같은 방식, 군단 합계는 장수 한도 안).
- 부대의 **훈련도**는 부대에 붙어 있어서, 누가 이끌어도 유지된다.

## 3. 등록·고용 공통 규칙

| 항목 | 내용 (초안) |
|---|---|
| 등록 내용 | 등록 시점의 **복사본**(스냅샷) |
| 원본 | 등록해도 내 장수·부대는 그대로 쓸 수 있다 |
| 갱신 | 더 키운 뒤 다시 등록하면 새 스냅샷으로 교체. 이력은 이어진다 |
| 등록 수 한도 | 장수·부대 각각 설정값 (예: 각 3개) |
| 등록 해제 | 언제든 가능 (고용 중인 건 그 전투가 끝난 뒤 해제) |
| 고용 화면 | 장수 목록 / 부대 목록 탭으로 나눔. 검색·정렬 (병종, 능력치, 승률, 가격, 레벨, 훈련도) |
| 고용 단위 | **전투 1회** (제안). 출진 준비에서 편성에 넣는다 |
| 지휘 | 고용한 유저가 자기 군단처럼 지휘한다 |
| 결과 영향 | 고용한 전투에서 병력이 줄거나 포로가 돼도 **원본에는 영향 없음** (확정). **이력에만 기록**된다 |
| 비용 자원 | **등록할 때 등록자가 선택**한다: 돈 또는 군량 (확정) |
| 보상 | 등록한 유저에게 지급. 부대는 **고용 인원에 비례** (비율·출처는 추후 결정) |
| 고용 가격 | **등록자가 정한다** (확정). 등록 화면에서 시스템이 **추천 가격(가이드)**을 보여주고, **최대 가격 제한**을 둔다 (3.1) |
| 제한 | 하루 고용 횟수, 같은 대상 연속 고용 대기시간 (설정값). 지금: 24시간에 10회, 같은 등록 30분 (예시, `balance.json` hire, R-44) |
| 자기 등록분 | 내가 등록한 장수·부대는 내가 고용할 수 없다 |

### 3.1 고용 가격

- 등록자가 가격과 **지불 자원(돈 / 군량)**을 정해서 등재한다.
- 장수는 **1회 고용 가격**, 부대는 **병사 1명당 가격**으로 정한다.
- 등록 화면에 **추천 가격**을 보여준다. 추천 가격은 전투력으로 계산한다.
  - 장수: 레벨, 능력치, 스킬·특성.
  - 부대: 병종 단계, 병력, 훈련도, 결속.
  - 이력이 좋으면(승률 등) 추천 가격을 올릴 수 있다 (선택).
- **최대 가격 제한**: 추천 가격의 일정 배수까지만 정할 수 있다 (예: 2배, 설정값). 너무 비싼 등록을 막는다.
- 공식과 배수는 `balance.json` 설정값.

## 4. 이력 (전투 기록)

등록된 장수·부대마다 **따로** 서버에 기록한다. 다른 유저가 고용 전에 본다. 부대 이력에는 "어떤 장수가 이끌었을 때 성적이 좋았나"도 남긴다.

| 기록 | 예 |
|---|---|
| 고용 횟수 | 128회 |
| 승률 | 72% (승 92 / 패 36) |
| 결과 분포 | 승리 · 패배 · **퇴각** · **포로** 횟수 |
| 전투 성과 | 평균 격파 병력, 평균 손실(사망·부상), 평균 생존율 |
| 상대 | 주로 이긴·진 상대의 전장 유형·진형 |
| 최근 전투 | 최근 N회: 날짜, 스텝(전장), 결과, 고용한 유저, 주요 수치. **바로 재생 가능** ([replay.md](replay.md)) |
| 등록 정보 이력 | 스냅샷이 바뀐 날짜와 레벨 변화 |
| 일기토 전적 (장수) | 승·패·퇴각·연승 |
| 원본 기록 (선택) | 등록한 유저가 직접 싸운 전투 기록도 공개할지 (결정 필요) |

- 기록은 **조작할 수 없어야** 한다 (5장).
- 지금 구현 (2026-11-09, R-44): 고용 횟수, 승·패·퇴각·포로·궤멸 횟수, 잃은 병력·고용 병력(→ 평균 생존율), 최근 전투(시각·스텝·결과·시작/잃은 병력, 10개). 격파 병력·상대 전장·고용한 유저·재생·일기토 전적은 아직.

## 5. 공정성 (서버 검증)

전투가 기기에서 계산되면 결과를 조작해 이력·보상을 부풀릴 수 있다. 그래서:

- 전투 규칙(Model)은 **고정 시드로 같은 입력이면 같은 결과**가 나오게 만든다 (이미 설계에 있음).
- 기기는 결과 대신 **전투 입력**(시드, 편성, 명령 기록)을 서버에 보낸다.
- 서버가 **같은 규칙 코드로 다시 계산(재현)**해서 결과를 확정하고, 그 결과로 이력·보상을 기록한다.
  - 서버에서 같은 전투 규칙 코드를 실행한다 (구현 방식: [../../impl/unity/decisions.md](../../impl/unity/decisions.md)).
- 재현 결과와 기기 결과가 다르면 기록하지 않는다.

- **내 등록 관리**: 장수 키우기 탭 또는 고용 탭 안에서 등록·갱신·해제, 받은 보상 확인.
- **출진 준비**: 편성 슬롯에 고용 장수 넣기.
- 지금 구현 (2026-11-09, 임시 화면, [../../impl/unity/architecture.md](../../impl/unity/architecture.md) 0.6): 고용 탭 = 장수/부대 목록(이력 한 줄·최근 3전, 오늘 고용 수)·내 등록 해제·등록(가격 정하기)·우편함(받기). 고용은 스토리 출진 화면의 "고용" 카드에서: 장수는 고른 군단의 **지휘관을 바꾸고**(그 군단의 부대는 그대로), 부대는 고른 군단의 **첫 빈 칸**에 넣는다. 부대 인원은 최대(등록 인원과 장수 한도의 남은 자리 중 작은 쪽)의 25·50·75·100% 중에서. 대기 중인 등록·하루 상한이 차면 고를 수 없다. 검색·정렬·상세는 다음 단계.

## 7. 장수·부대 키우기와의 관계

- 장수 키우기·부대 키우기는 이 기능 때문에 **핵심 컨텐츠**가 된다 (키운 결과가 수익이 됨).
- 키우기 탭의 세부 컨텐츠는 나중에 구성하지만, **등록 가능한 데이터 형태**(스냅샷)는 지금 정의해 둔다.
