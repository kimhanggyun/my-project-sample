# 테마 교체 (옛날 전투 → 판타지 등)

> 상태: 설계 원칙 (구현 전)
> 지금은 **옛날 전투 테마**(동양풍 고대 전쟁, 자체 세계관)로 만들지만, 나중에 **판타지 전투 등 다른 테마로 바꿀 수 있게** 처음부터 분리한다.

---

## 0. 세계관

- 이 게임은 **삼국지가 아니다.** 「삼국지 와룡전」은 **전투 장면 일부를 참고**했을 뿐이다.
- 세계관·인물·지명은 자체로 만든다. 지금은 **익명·임시 이름**으로 채우고 나중에 정한다.

## 1. 원칙

1. **규칙 코드는 테마를 모른다.** 전투·성장·경제 코드에는 장수 이름, "궁병", "군량" 같은 단어가 없다. 모두 영문 id로 다룬다.
2. **화면에 보이는 모든 것은 테마 팩에 있다.** 이름, 문구, 대사, 초상화, 3D 모델, 아이콘, UI 스킨, 사운드.
3. **규칙 데이터와 테마 데이터를 나눈다.** 수치(능력치, 상성, 보정값)는 규칙 데이터, 이름·그림은 테마 데이터. 테마를 바꿀 때 규칙 데이터는 그대로 쓰거나 테마에 맞게 덮어쓴다.
4. **기획 문서는 현재 테마(옛날 전투) 용어로 쓴다.** 단, 데이터 예시의 키는 영문 id를 쓴다.

---

## 2. 테마 팩에 들어가는 것

| 항목 | id (공통) | 옛날 전투 테마 (현재) | 판타지 테마 (예) |
|---|---|---|---|
| 지휘관 | `general` | 장수 | 영웅 |
| 능력치 | `leadership` / `might` / `intellect` | 통솔 / 무력 / 지략 | 지휘 / 힘 / 마력 |
| 병종 | `infantry` / `spearman` / `archer` / `cavalry` / `scout` (전체 목록: [content/troops.md](content/troops.md)) | 보병 / 창병 / 궁병 / 기병 / 첨병 | 검사 / 창기사 / 궁수 / 기사 / 정찰병 |
| 진형 | `fishScale`, `craneWing` … | 어린, 학익 … | 쐐기 대형, 포위 대형 … |
| 스킬 | `ambush`, `fireAttack` … | 복병, 화계 … | 매복, 화염구 … |
| 자원 | `supply` | 군량 | 식량 / 보급품 |
| 자원 | `gold` | 돈 | 금화 |
| 포로 시설 | `prisonCamp` | 수용소 | 감옥 |
| 세력 | `faction` | 자체 세계관의 나라·세력 (임시 이름) | 왕국, 마왕군 … |
| 대사·스토리 | 스텝별 대사 파일 | 자체 스토리 (나중에 입력) | 판타지 스토리 |
| 그림·모델 | 초상화, 장수·병사 3D 모델, 아이콘 | 갑옷·창·말 | 기사·마법사·몬스터 |
| UI 스킨 | 색, 글꼴, 프레임 | 동양풍 | 서양 판타지풍 |
| 사운드 | 배경음, 효과음 | 동양 악기 | 오케스트라 |

---

## 3. 데이터 키 규칙

- 데이터의 키와 참조는 **영문 id**만 쓴다.
- 화면 표시는 테마 문자열 표에서 찾는다 (`nameKey`).

```json
// 규칙 데이터 (테마 공통): troopTypes.json
{ "id": "archer", "tags": ["ranged"], "stats": { "range": 60, "attack": 45 } }

// 테마 데이터: themes/ancientwar/strings.ko.json
{ "troop.archer": "궁병", "stat.intellect": "지략", "resource.supply": "군량" }

// 테마 데이터: themes/fantasy/strings.ko.json
{ "troop.archer": "궁수", "stat.intellect": "마력", "resource.supply": "식량" }
```

- 언어(한국어·영어 등)도 같은 방식으로 문자열 표만 바꾸면 된다.

## 4. 판타지에서 새로 필요할 수 있는 규칙과 붙이는 방법

| 새 요소 | 붙이는 방법 (기존 확장 지점) |
|---|---|
| 비행 유닛 (지형·성벽 무시) | 병종 태그 `flying` + 이동 비용 보정 규칙 추가 |
| 마법 공격 | 스킬 효과(`ISkillEffect`) 조합. 새 효과 종류는 클래스 추가 |
| 마나 등 새 자원 | 자원 종류 데이터 추가, 스킬 비용으로 연결 |
| 몬스터 군단 (장수 없음) | 군단 데이터에 "지휘관 없음" 옵션, 사기·퇴각 규칙은 데이터로 조정 |
| 새 능력치 (예: 마법 저항) | `stats.json` 추가 + 보정 규칙 추가 |
| 새 전장 유형 (던전 등) | `IBattleTypeRules` 구현 + 지형 부품 |

모두 **추가**로 붙고, 기존 전투 코드는 수정하지 않는 것이 목표다.

## 5. 폴더 구조

```
Data/
├─ Rules/                       테마 공통 규칙 데이터 (balance, stats, formations 배치·상성 …)
└─ Themes/
    ├─ ancientwar/              현재 테마 (옛날 전투)
    │   ├─ strings.ko.json      이름·문구
    │   ├─ generals.json        장수 목록 (id, 능력치, 초상화 키)
    │   ├─ troopTypes.json      테마별 병종 (규칙 데이터 덮어쓰기 가능)
    │   ├─ Steps/ , Story/      스토리·스텝·대사
    │   └─ startingKit.json
    └─ fantasy/                 나중에 추가
Assets/Themes/ancientwar/        초상화, 3D 모델, 아이콘, UI 스킨, 사운드
```

- `ThemeManager`가 사용할 테마를 정한다 (빌드 설정 또는 앱 설정).
- 테마 데이터는 규칙 데이터를 **덮어쓸 수 있다** (예: 판타지에서 궁수 사거리를 더 길게).

---

## 6. 지금 단계에서 지킬 것

- 코드·데이터에 한국어 이름을 키로 쓰지 않는다.
- 화면 문구를 코드에 직접 쓰지 않고 문자열 표에서 가져온다.
- 3D 모델·그림은 테마 폴더 아래에 둔다.
- 전투 규칙에 현재 테마에만 맞는 가정(예: "장수는 항상 사람")을 넣지 않는다. 필요하면 데이터 옵션으로 둔다.
