# 부품 꾸미기 (UI 키트)

> 상태: 2026-11-27 제안 → **PR 1 구현** (틀 + 바탕 · 버튼 · 탭). 목록 = `data/Ui/uiKit.json`, 값 = `styles.json` parts, 코드 = `UiKit.cs` (값 읽기 · 개발 값 · 내보내기 · 바탕 · 버튼 · 뒤로가기 · 출진 · 탭 줄), `SegmentArt.cs` (코드 그림), 화면 = `PartsKitView.cs` (개발 줄 [부품]). 카드 체계(PR 2) · 움직임 · 머리 · 창(PR 3)은 아직.
> 관련: [mockups/공통부품.md](mockups/공통부품.md) (역할 목록 · 쓰는 페이지), [art-direction.md](art-direction.md), `data/Ui/styles.json`, 메인 세그먼트 그림 탭 (#302) · 자주 테마 (#302 · #303).

## 0. 왜

- 지금은 "Claude가 고침 → 캡처 → 확인"을 부품마다 되풀이해서 느리다.
- 병사 꾸미기처럼 **부품 꾸미기 화면**에서 사용자가 직접 모양을 바꿔 보고, 정한 값을 데이터로 내보내 PR한다.
- 카드처럼 여러 화면에서 쓰는 부품을 **종류 · 밀도별로 정리**해야 전투의 부대 고르기 같은 새 화면도 같은 카드를 그대로 쓴다.

## 1. 네 층

화면은 **역할**만 부르고, 모양은 아래 네 층을 차례로 따른다.

| 층 | 무엇 | 누가 정하나 | 어디에 |
|---|---|---|---|
| **테마** | 색 묶음 (바탕 · 판 · 강조 · 밝은 강조 · 글자 · 흐린 글자 · 선 · 좋음/나쁨 …) | 사용자 (꾸미기 화면) | `styles.json` `styles.<id>.colors` (지금 있음) |
| **역할** | 화면에서 부르는 이름 (`button.primary`, `card.troop`, `bg.page` …) | 설계 (이 문서 · 공통부품.md) | 코드 |
| **변형** (모양 종류) | 그 역할의 그리는 방식 (각진 / 둥근 / 알약 / 아이콘만 / 장식 테두리 …) | 사용자가 고름, 그리는 코드는 Claude | 코드에 등록, 데이터는 이름만 |
| **값** | 변형마다 열어 둔 조절값 (높이 · 글자 크기 · 둥글기 · 테두리 두께 · 색 이름 · 그림 id · 흐림 · 진하기 · 애니 켜기/속도 …) | 사용자 (꾸미기 화면) | `styles.json` `parts.<역할>` |

- 색은 값에 hex를 직접 쓰지 않고 **테마 색 이름**(`accent`, `card`, `line` …)으로 고른다. 그래야 테마를 바꾸면 모든 부품이 따라간다. (꼭 필요하면 hex 허용)
- 변형은 **새 기능 = 구현 추가 + 등록** 원칙대로: 새 변형은 그리는 코드 하나를 더하고 목록에 등록. 기존 변형은 고치지 않는다.
- 그림이 있으면 그림 먼저: 모든 코드 그림은 `Resources/Ui/<그림 id>` 파일이 있으면 그것을 쓴다 (지금 `UiArt` · `SegmentArt`와 같은 방식).

## 2. 그림 자원 (공용 그림 목록)

부품이 "그림 id"로 골라 쓰는 공용 그림. 처음엔 코드로 그린 실루엣 · 무늬, 나중에 일러스트로 바꿔 끼운다.

| 종류 | id 예 | 쓰는 곳 | 첫 버전 |
|---|---|---|---|
| **흐린 배경 그림** | `scene.army` (전쟁의 웅장함: 끝없는 대열 · 먼지), `scene.flags` (깃발 든 진군), `scene.castle` (성과 산), `scene.camp` (진영 · 막사), `scene.duel` (두 장수 맞섬) | 바탕 · 세그먼트 · 카드 머리 · 배너 | 코드 실루엣 3~4종 |
| **인물 실루엣** | `fig.general` (투구 얼굴), `fig.troop5` (병사 5명), `fig.command` (장군이 가리킴), 병종별 `fig.infantry` · `fig.spear` · `fig.archer` · `fig.cavalry` | 세그먼트 · 아이콘 · 빈 카드 | 앞의 3개는 있음 (#302) |
| **장식 테두리** | `frame.plain`, `frame.arrowTwist` (화살이 꼬여 두른 테두리), `frame.knot` (매듭 모서리), `frame.ink` (먹선, 지금 있음) | 버튼 · 카드 · 창 | 코드 9-slice |
| **모서리 장식** | `orn.cloud` (구름), `orn.flame`, `orn.corner` | 고른 칸 · 강조 카드 | 코드 |
| **아이콘** | `ico.back` (활 모양 뒤로가기), `ico.sortie` (교차 검), 탭 아이콘 (영토 · 군대 · 대전 · 모집 · 연합 · 도감), 자원 · 능력치 | 버튼 · 탭 · 칩 | 코드 도형 → 나중에 붓 터치 그림 |
| **움직임** | `anim.horseRun` (말 달림), `anim.swordClash` (검과 검이 맞부딪쳐 불꽃), `anim.flagWave` (깃발 펄럭), `anim.drum` (북 울림) | 출진 버튼 · 로딩 · 승리 | 코드 애니 |

## 3. 꾸미기 화면 구성

개발 빌드 전용 (아래 개발 줄 탭 **[부품]**을 이 화면으로 키움, 기존 `PartsTabView`).

- **위 세그먼트 = 종류**: 테마 · 바탕 · 버튼 · 탭 · 카드 · 막대 · 글자 · 창(겹침) · 머리(상단 바 · 뒤로가기) · 움직임(로딩 · 출진)
- **가운데 미리보기**: 고른 부품을 실제 크기로, **상태별로 나란히** (보통 · 눌림 · 꺼짐 · 고름 · 경고 · 처리 중). 휴대폰 화면 틀 안에 실제 배치로 보는 **[화면에 놓고 보기]** (메인 · 편성 · 상점 하나씩).
- **아래 조절판**:
  - 변형 고르기 (그림 칩 목록)
  - 값: 색 (테마 색 이름 칩 + hex 입력) · 슬라이더 (높이 · 글자 · 둥글기 · 테두리 · 흐림 · 진하기 · 속도) · 켜기/끄기 · 그림 id 고르기
  - 읽힘 경고: 글자와 바탕 대비가 낮으면 빨간 표시, 누르기 칸이 88(기준 1080 폭)보다 작으면 표시
- **비교**: A/B 두 칸 나란히 (지금 값 vs 바꾼 값)
- **저장 · 내보내기**: [저장] = 개발 값으로 (병사 꾸미기 DevLooks와 같은 방식, 다시 켜도 남음) · [되돌리기] · [데이터로 내보내기] = `styles.json`에 씀 → 사용자 "PR·머지"
- **캡처 투어**: 종류마다 한 장 + 화면에 놓고 보기 3장

## 4. 종류별 부품 · 변형

### 4.1 바탕 (`bg.*`)

| 역할 | 변형 | 값 |
|---|---|---|
| `bg.page` (페이지 바탕) · `bg.panel` (판) · `bg.header` (머리 띠) | `none` (아무것도 없음, 투명) · `solid` (색) · `texture` (한지 · 비단 무늬) · `scene` (흐린 그림) · `gradient` (위아래 색 번짐) | 색 이름 · 그림 id · 흐림 · 진하기 · 맞춤 (`fit` 안 자름 / `fill` 채움) · 위치 (위 · 가운데 · 아래) · 글자 뒤 그림자 켜기 |

### 4.2 버튼 (`button.*`)

| 역할 | 변형 | 값 |
|---|---|---|
| `button.primary` · `button.secondary` · `button.small` · `button.icon` · `button.back` · `button.sortie` | `square` (각진) · `round` (둥근) · `pill` (끝이 반원) · `icon` (아이콘만) · `iconText` (아이콘 + 글자) · `framed` (장식 테두리: 화살 꼬임 · 매듭 · 먹선) · `scene` (뒤에 흐린 그림, 세그먼트처럼) | 둥글기 · 테두리 두께 · 테두리 그림 id · 아이콘 id · 색 (바탕 · 테두리 · 글자) · 높이 · 글자 크기 · 눌림 효과 (어둡게 · 눌려 들어감) |
| `button.back` (뒤로가기) | `chevron` (‹, 지금) · `bow` (활을 뒤로가기 모양으로) · `text` | 크기 · 색 |
| `button.sortie` (출진) | `plain` · `run` (말 달림 + 길 무늬, 시안) · `clash` (검 부딪침) | 애니 켜기 · 언제 (늘 · 누를 때) · 속도 |

### 4.3 탭 (`tabs.*`)

| 역할 | 변형 | 값 |
|---|---|---|
| `tabs.segment` (페이지 안 나눔) · `tabs.art` (그림 세그먼트, 메인) · `tabs.chip` (작은 거르기) · `tabs.bottom` (아래 탭 바) | `button` (버튼 줄, 지금) · `underline` (밑줄) · `art` (흐린 그림 + 가운데 글자, #302) · `icon` · `iconText` | 높이 · 고른 칸 색 · 밑줄 · 테두리 · 그림 id(칸마다) · 아이콘 id |

### 4.4 카드 (`card.*`) — 내용 × 밀도 × 틀

카드는 **무엇을 보이나(내용)**, **얼마나 자세히(밀도)**, **겉모양(틀)** 세 가지로 나눈다. 화면은 `Ui.Card(내용, 밀도, 데이터)`처럼 부르고, 틀은 스타일 데이터가 정한다. → 전투 부대 고르기에서도 `card.troop` · `card.corps`의 같은 밀도를 그대로 씀.

**내용**

| 내용 | 넣는 것 (밀도가 높을수록 더) |
|---|---|
| `general` 장수 | 초상 · 이름 · 등급 · Lv · 상태 → 통 · 무 · 지 → 특성 · 스킬 · 병종 적성 |
| `troop` 병종 | 병종 그림 · 이름 · 인원 → 훈련 · 결속 · 부상 → 공 · 방 · 상성 · 승급 |
| `corps` 군단 (편성) | 장수 초상 · 진형 · 총 인원 → 병종 칸별 인원 → 역할 · 군량 · 진형 미리보기 |
| `item` 꾸미기 · 상품 | 그림 · 이름 · 값 → 등급 · 얻는 길 |
| `step` 스토리 스텝 · `replay` 녹화 · `mail` 우편 | (공통부품.md 그대로) |

**밀도**

| 밀도 | 크기 (기준 1080 폭) | 쓰는 곳 |
|---|---|---|
| `mini` 미니 | 138~180 정사각 · 그림 + 숫자 하나 | 편성 보유 줄 · 전투 부대 고르기 줄 |
| `compact` 간편 | 한 줄 높이 120~160 · 그림 + 이름 + 핵심 값 1~2 | 목록 · 출진 준비 · 전투 선택 패널 |
| `standard` 보통 | 높이 220~260 (지금 병력 목록) | 탭 목록 |
| `detail` 세밀 | 반 화면 이상 · 모든 값 | 상세 · 정보 판 |

**틀**

| 변형 | 값 |
|---|---|
| `plain` (판만) · `strip` (왼쪽 강조 띠, #303) · `grade` (등급 색 테두리) · `framed` (장식 테두리) · `scene` (머리에 흐린 그림) | 띠 굵기 · 테두리 두께 · 둥글기 · 그림 id · 그림 뒤 판 색 |

상태 (모든 카드 공통): 보통 · 고름 · 흐림(다 씀 · 못 나감) · 경고(넘침) · 잠김.

### 4.5 막대 · 게이지 (`bar.*`)

`bar.gauge` (병력 · 훈련) · `bar.hp` (전투 체력 · 책략) · `bar.power` (전력 비교) · `bar.rate` (확률): 변형 `flat` · `round` · `segmented` (칸 나뉨) · `brush` (붓 획 끝). 값: 두께 · 빈 바탕(`track`) · 채움 색 · 숫자 위치.

### 4.6 글자 (`text.*`)

제목 · 구역 머리말 · 본문 · 숫자 · 꼬리표: 글꼴 (제목 · 본문) · 크기 · 굵기 · 색 · 테두리/그림자 (그림 위 글자).

### 4.7 창 · 겹침 (`pop.*`)

확인 창 · 아래 판 · 말풍선 · 알림 띠: 바탕 변형 (`solid` · `scene` · `framed`) · 뒤 어둡게 정도 · 나타나는 움직임 (없음 · 올라옴 · 펼쳐짐).

### 4.8 머리 (`head.*`)

상단 자원 바 · 페이지 머리 (뒤로가기 + 제목 + ⓘ): 바탕 (`bg.header`) · 뒤로가기 변형 (4.2) · 자원 칩 변형 (`pill` · `seal` 낙관) · 제목 꾸밈 (없음 · 붓 획 · 밑줄).

### 4.9 움직임 (`anim.*`)

| 역할 | 변형 | 값 |
|---|---|---|
| `anim.loading` (로딩) | `ring` (지금) · `swordClash` (검이 맞부딪치며 불꽃) · `horseRun` · `flagWave` | 크기 · 속도 · 색 |
| `anim.press` (누름) | `none` · `shrink` · `flash` | 세기 |
| `anim.sortie` | 4.2 출진 참고 | |

## 5. 데이터 모양 (`styles.json` 늘림)

```json
"parts": {
  "button.primary": { "variant": "pill", "height": 120, "fontSize": 40, "color": "accent", "border": "accentLight", "borderWidth": 3 },
  "button.back":    { "variant": "bow", "size": 72 },
  "tabs.art":       { "variant": "art", "height": 96, "art": ["fig.general", "fig.troop5", "fig.command"] },
  "bg.page":        { "variant": "scene", "art": "scene.flags", "blur": 0.6, "alpha": 0.25, "fit": "fit" },
  "card.troop.compact": { "variant": "strip", "strip": 7, "pictureBack": "pictureBack" },
  "anim.loading":   { "variant": "swordClash", "speed": 1 }
}
```

- 지금 있는 `color` · `textColor` · `height` · `fontSize`는 그대로 읽는다 (예전 데이터 호환).
- 페이지 덮어쓰기 (`pages`)도 그대로: 예 `pages.battle.card.troop.compact = "card.troop.compact.dark"`.
- 데이터 검사 테스트: 변형 이름이 등록된 것인지, 색 이름이 테마에 있는지, 그림 id가 목록에 있는지, 높이 · 크기 범위.

## 6. 지킬 것

- **색 겹침 피하기** (2026-11-26 사용자): 강조색은 맵(초록 · 회색 · 갈색 · 물색) · 팀(파랑 · 빨강) · 갑옷 · 말 색과 겹치지 않게. 꾸미기 화면 색 칩에 경고 표시.
- 누르기 칸 최소 88, 글자 대비 낮으면 경고.
- 그림은 코드로 그린 것을 한 번 만들어 캐시 (화면마다 다시 그리지 않음).
- 규칙 코드와 무관 (화면 층만). 테마 · 변형을 꺼도 기본 모양으로 동작.
- 나중에 플레이어용 UI 스킨(판매 등)으로 쓸 수도 있지만, 지금은 개발용. 정할 때 사용자와 의논.

## 7. 만드는 순서 (PR 3개로 묶음)

| PR | 내용 | 끝나면 |
|---|---|---|
| **1. 틀 + 바탕 · 버튼 · 탭** | 변형 등록 구조, `parts`의 variant · 값 읽기, 꾸미기 화면 (세그먼트 · 미리보기 · 조절판 · 저장 · 내보내기 · 비교), 바탕 변형 전부 + 흐린 배경 그림 3종, 버튼 변형 (각진 · 둥근 · 알약 · 아이콘 · 아이콘+글자 · 장식 테두리 2종 · 활 뒤로가기 · 출진 말 달림), 탭 변형 (아래 탭 아이콘 포함), 남은 것 (주변 부대 글자) | 사용자가 바탕 · 버튼 · 탭을 직접 꾸밈 |
| **2. 카드 체계** | 카드 = 내용 × 밀도 × 틀, 장수 · 병종 · 군단 · 아이템 × 미니 · 간편 · 보통 · 세밀, 지금 화면들을 새 카드로 바꿈 (모양은 지금과 같게 시작) | 전투 부대 고르기가 같은 카드를 씀 |
| **3. 움직임 · 머리 · 창** | 로딩 (검 부딪침 · 말 · 깃발), 누름 효과, 상단 바 · 페이지 머리 변형, 창 바탕 · 나타남 | 화면 전체가 꾸미기 화면으로 조절됨 |

각 PR은 캡처 한 번으로 확인 (꾸미기 화면 종류별 + 화면에 놓고 보기). 그 뒤 모양 정하기는 사용자가 꾸미기 화면에서 → [내보내기] → "PR·머지".
