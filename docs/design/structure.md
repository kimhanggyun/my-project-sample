# 구조 설계 (엔진 무관)

> 상태: 설계 뼈대 · **엔진·언어와 무관**
> 이 문서는 "무엇을 어떤 모듈이 맡고, 모듈끼리 무엇을 주고받는가"만 정한다.
> 특정 엔진으로 만드는 방법(클래스·폴더·SDK)은 구현 문서에 있다: [Unity 구현](../impl/unity/architecture.md)

---

## 1. 원칙

1. **규칙과 화면 분리.** 게임 규칙(전투·성장·경제·포로·고용)은 화면·엔진을 모른다. 화면은 규칙의 상태와 이벤트를 받아 보여주기만 한다.
2. **데이터 주도.** 수치·이름·종류는 데이터(JSON). 코드는 규칙만 가진다.
3. **테마 분리.** 데이터 키는 영문 id. 화면 문구·그림·대사는 테마 팩 ([theme.md](theme.md)).
4. **확장은 추가로.** 새 명령·진형·스킬·승리 조건·전장 유형·탭은 기존 코드를 고치지 않고, 정해진 확장 지점에 구현을 **추가하고 등록**해서 붙인다.
5. **결정적 전투.** 같은 입력(시드·편성·명령 기록)이면 같은 결과. 서버 재현 검증, 리플레이, 자동 시뮬레이션의 기반.
6. **수치는 실수.** 능력치 1~100, 소수점 허용. 능력치 항목은 데이터로 정의하고 이름(id)으로 조회한다.
7. **바깥 서비스는 경계 뒤에.** 로그인·결제·광고·서버·시간은 추상화된 경계(인터페이스) 뒤에 두고, 구현은 교체 가능하게 한다.

## 2. 모듈 지도

```
              ┌──────────── 화면 (UI · 전투 화면) ────────────┐
              │  메인·탭·출진 준비·결과 / 전장 표시·입력·카메라  │
              └───────────────┬──────────────────────────────┘
                              │ 상태 읽기 · 명령 보내기 · 이벤트 받기
 ┌───────────┬───────────┬────┴──────┬───────────┬───────────┬───────────┐
 │  전투     │  성장     │ 진행      │  경제     │  고용     │  테마     │
 │ (Battle)  │(Progress.)│(Campaign) │ (Economy) │ (Online)  │ (Theme)   │
 └─────┬─────┴─────┬─────┴─────┬─────┴─────┬─────┴─────┬─────┴───────────┘
       └───────────┴─────┬─────┴───────────┴───────────┘
                    데이터 (Data)
       ─────────────── 바깥 경계 ───────────────
        로그인 · 결제 · 광고 · 서버 · 저장 · 시간
```

| 모듈 | 책임 | 입력 | 출력 |
|---|---|---|---|
| **Data** | 데이터 읽기, 공통 기본값 + 스텝·테마별 덮어쓰기 병합 | 데이터 파일 | 규칙에 쓸 최종 값 |
| **Battle** | 전투 규칙 전체 (실시간 시뮬레이션) | `BattleSetup` | `BattleResult`, 상태·이벤트, 명령 기록 |
| **Progression** | 경험치·레벨·능력치 계산, 승급·해금 | `BattleResult`, 성장 입력 | 장수·부대 성장 상태 |
| **Campaign** | 스텝 진행, 장수 상태(포로 등), 구출·등용, 병력 관리 | `BattleResult`, 시간 | 진행 상태 |
| **Economy** | 자원(군량·돈), 출진 군량, 징병·모병·치료, 결제 상품 효과 | 행동, 결제 결과 | 자원 변화 |
| **Online** | 장수·부대 등록·고용, 이력, 전투 기록 제출 | 스냅샷, 명령 기록 | 고용 결과, 이력 |
| **Theme** | 테마 선택, 문구, 그림·모델·사운드 | 테마 id, 문구 키 | 화면에 보일 것 |
| **Ads** | 배너 표시 규칙, 보상형 광고, 광고 제거 권한 | 현재 화면, 권한 | 광고 표시, 보상 |
| **Auth** | 자동 로그인, 게스트, 계정 연동 | - | 계정 |
| **Core** | 앱 시작 순서, 화면 전환, 저장, 설정 | - | - |
| **UI / 전투 화면** | 메인·탭·출진·결과 화면, 전장 표시·터치 입력 | 각 모듈 상태 | 명령, 화면 이동 |

## 3. 전투 모듈

규칙: [content/battle.md](content/battle.md)

### 3.1 입구와 출구

```
BattleSetup  ──▶  전투  ──▶  BattleResult
```

| 경계 | 내용 |
|---|---|
| `BattleSetup` | 맵, 전장 유형, 양측 군단(장수·소부대·병종·진형·병력), 군량, 사용 가능한 진형·스킬, 승패 조건, 이벤트, 시드, 설정값 |
| `BattleResult` | 승패, 군단별 남은 병력·사망·부상, 장수 결과(퇴각·포로), 공적, 포획 군량, 명령 기록 |

- 지금은 스토리 스텝 + 편성에서 `BattleSetup`을 만든다. 나중에 전략 지도 등 다른 진행 방식도 같은 형식을 만들면 된다.

### 3.2 내부 시스템 (각각 독립된 단위)

| 시스템 | 책임 |
|---|---|
| 명령 | 군단 명령 예약을 순서대로 실행 |
| 진형 | 장수 기준 소부대 자리, 진형 변경·회전, 좁은 길 종대 전환 |
| 경로 | 장수 기준 군단 경로 탐색 |
| 이동 | 소부대·병사 추종 이동, 병사 간 밀어내기 |
| 소부대 판단 | 행동 후보 점수 → 최고점 행동 선택 (능력치 기반 자율 판단) |
| 대상 선정 | 공격 대상 고르기 |
| 교전 | 근접 교전, 피해 적용 (병력 숫자) |
| 원거리 | 사거리 안의 보이는 적 공격 |
| 피해 계산 | 보정값(%p) 합산 → 상·하한 → 기본 피해에 한 번 적용, 보정 내역 반환 |
| 지휘 영향 | 장수 능력치 → 규율·용맹 → 소부대 보정, 지휘 범위 |
| 사기 | 사기 증감, 사기 보정 |
| 퇴각 | 퇴각 판정·이동·이탈 |
| 포로 | 포위 판정, 포로 확률, 탈출 |
| 군량 | 소비, 소진 시 사기 하락, 포획 집계 |
| 시야 | 부대별 시야 → 진영 공유 보임 격자, 마지막 목격 위치 |
| 탐지 | 은신 탐지 |
| 스킬 | 사용 조건·대상·효과 실행 |
| AI | 적·위임 군단의 군단 명령 |
| 이벤트 | 대사·증원 조건 감시 |
| 승패 | 승리·패배 조건 판정 |
| 일기토 | 전투 시작 직전 발생·결과 |
| 명령 기록 | 모든 명령을 시간(틱)과 함께 기록 → 서버 재현·리플레이 |

### 3.3 확장 지점

| 확장 지점 | 구현 예 | 데이터에서 고르는 키 |
|---|---|---|
| 군단 명령 | 돌격, 공격, 대형, 성벽, 수비, 후퇴 | 명령 id |
| 명령 예약 항목 | 이동, 공격 대상, 스킬, 접근 후 스킬 | 입력에서 생성 |
| 소부대 행동 | 진형 유지, 최근접 처리, 유리한 상대, 빈 곳 메우기, 아군 지원, 측면, 후퇴 | 행동 목록·가중치 |
| 피해 보정 | 병종 상성, 방향, 지형, 진형 상성, 돌파력, 용맹, 사기, 스킬 | 보정값 |
| 시야 보정 | 병종, 장수, 지형, 진형·명령, 날씨 | 보정값 |
| 군단 AI | 공격형, 방어형, 성벽 수비, 위임 | `ai` |
| 승리 조건 | 대장 격파, 성 점령, 버티기, 군량 소진, 구역 점령, 시설 파괴 | `victory`, `defeat` |
| 스킬 대상 | 자신, 아군, 적, 지점, 범위, 방향 | `target.type` |
| 스킬 효과 | 피해, 버프, 디버프, 사기, 진형 혼란, 이동, 은신, 기습 | `effects[].type` |
| 스킬 조건 | 능력치 이상, 레벨 이상, 병종 태그 | `requires` |
| 전장 유형 규칙 | 야전, 성새전, 수상전 | `battleType` |

## 5. 바깥 경계 (교체 가능한 구현)

| 경계 | 하는 일 | 지금 (서버 없음) | 나중 |
|---|---|---|---|
| 저장 | 세이브 읽기·쓰기 | 기기 저장 | 클라우드 저장 |
| 시간 | 현재 시각 | 기기 시계 | 서버 시간 |
| 로그인 | 계정 | 게스트(기기) | 백엔드 서비스 로그인 + 플랫폼 로그인 |
| 결제 | 구매·복원 | 테스트용 가짜 | 구글 플레이·앱스토어 |
| 영수증 검증 | 구매 진위 | 기기 검증 | 서버 검증 |
| 광고 | 배너·보상형 | 테스트용 가짜 | 광고 서비스 |
| 온라인 | 등록·고용·이력·전투 검증 | 없음 | 서버 |

## 6. 확장 시나리오

| 추가하고 싶은 것 | 해야 할 일 | 기존 규칙 수정 |
|---|---|---|
| 스텝·장수·진형·병종 | 데이터 추가 | 없음 |
| 능력치 항목 | 능력치 정의 데이터 + 그 능력치를 쓰는 규칙 추가 | 없음 |
| 명령·행동·스킬 효과·승리 조건 | 해당 확장 지점에 구현 추가·등록 | 없음 |
| 성새전·수상전 | 전장 유형 규칙 + 지형 부품 + 맵 | 없음 |
| 메인 탭 | 탭 모듈 + 탭 목록 데이터 | 없음 |
| 로그인 수단 (카카오 등) | 로그인 수단 구현 + 버튼 목록 데이터 | 없음 |
| 전략 지도 진행 | `BattleSetup` 생성 + `BattleResult` 처리 | 전투 없음 |
| 테마 (판타지 등) | 테마 팩 | 없음 |
| 엔진 교체 | 새 구현 문서(`impl/<엔진>/`) + 같은 설계·데이터 사용 | 설계 없음 |

## 7. 검증 도구 (엔진 무관 요구사항)

| 도구 | 목적 |
|---|---|
| 자동 시뮬레이터 | 화면 없이 전투를 대량 실행해 승률·손실·시간 비교 |
| 진형 상성 회귀 테스트 | 같은 능력치로 36개 진형 조합 → 상성표대로 승패 |
| 성장 곡선 시뮬레이션 | 스텝 1~N 자동 진행, 레벨 vs 권장 레벨 |
| 실시간 조정 패널 | 개발 빌드에서 보정값 즉시 변경 |
| 개발 메뉴 | 경험치·군량 지급, 스텝 해금, 세이브 내보내기·불러오기, 시간 빨리 감기 |
