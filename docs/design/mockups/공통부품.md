# 공통 부품 (시안에서 반복되는 것)

> 화면은 **부품만 놓는다**. 부품 모양은 `unity/Assets/Game/Scripts/UI/`(`Ui.cs`·`UiParts.cs`)의 공통 함수 한 곳에서만 만든다.
> 처음 정리: 2026-11-14 (01~03) → 05·06 보탬 → **2026-11-14 07 확정 때 역할·스타일·페이지 기준으로 다시 짬** (사용자 결정).

## 0. 원칙: 역할 · 스타일 이름 · 페이지

1. **화면 코드는 부품을 "역할"로만 부른다** — 주요 버튼, 보조 버튼, 미니 카드 … (색·크기를 화면에서 직접 정하지 않는다).
2. **모양은 스타일 데이터의 이름으로 정한다** (`data/Ui/styles.json`): 역할마다 기본 스타일 이름(예: `button.secondary` → `default`)이 있고, 스타일 이름마다 색·테두리·둥글기·높이·글자 크기.
3. **페이지마다 바꿀 수 있다**: 데이터에서 "이 페이지의 이 역할 = 이 스타일 이름"(예: `pages.formation.button.secondary = "small"`)으로 덮어쓴다. 코드는 바꾸지 않는다.
4. **부품 미리보기 페이지**: 개발 줄 탭 **[부품]**에 모든 부품 × 상태(켜짐·꺼짐·처리 중·흐림·경고 …)를 늘어놓는다. 스타일을 바꾸면 여기서 한 번에 확인.
5. 새 화면 시안을 확정할 때 **이 표에 없는 모양이 나오면** 부품을 먼저 더하고 화면은 그것을 쓴다.
6. **글자를 줄인다** (2026-11-14 10 확정 때 사용자 결정): 그림으로 보일 수 있는 건 **아이콘 · 도형 · 병종 그림 · 깃발 · 색**으로, 글자는 **숫자와 2~3자 꼬리표**만. 설명 문장은 **구역마다 작은 ⓘ → 말풍선**으로 옮긴다 (모르는 사람만 누름). 01~09 화면도 구현할 때 이 기준으로 글자를 줄인다.

> 상태 (2026-11-14 07 구현): 1 ✓. 2·3 ✓ — `styles.json`의 `parts`(스타일 이름 → color·textColor·height·fontSize)·`pages`(페이지 → 역할 → 스타일 이름), 코드 `UiStyle.Part(role)`·`UiStyle.Page`·`Ui.Styled(button, role)`. 지금 스타일을 입는 역할: `button.small`, `tabs.segment(.on)` — 다른 역할도 부품마다 차례로 `Styled`를 단다. 4 ✓ — 개발 줄 **[부품]** 탭 (`PartsTabView`).

표의 **구현**: ✓ = 공통 함수 있음, ○ = 시안 확정·아직 없음.
