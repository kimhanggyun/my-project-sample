## 1. 구현 후보

| 항목 | 후보 (잠정) | 이유 | 관련 요구사항 |
|---|---|---|---|
| 엔진 | Unity | 모바일 3D, 안드로이드·아이폰 동시 출시 | 플랫폼 |
| 버전 | Unity 6 LTS (시작 시점 최신 LTS) | 장기 지원, 대량 렌더링 개선 | 병사 대량 표시 |
| 렌더링 | URP | 모바일 기본 파이프라인 | 성능 |
| 3D 아트 | 장수는 세밀하게, 병사는 스타일라이즈드(로우폴리 + 카툰) | 대량 병사를 저사양 폰에서도 표시 | 화면 병사 최대한 많이 |
| 대량 병사 | GPU 인스턴싱, 애니메이션 굽기, 거리별 단순화, 품질 자동 조정 | 성능 | 화면 병사 최대한 많이 |
| 대량 처리 확장 | 필요 시 DOTS | 병사 수천 단위 | |
| 언어 | C# (규칙은 Unity 비의존 순수 C#) | 서버에서도 같은 코드로 전투 재현 | 결정적 전투, 서버 검증 |
| 데이터 | JSON (StreamingAssets) | 텍스트 편집, 클라우드에서도 수정 | 데이터 주도 |
| 결제 | Unity IAP (구글 플레이 + 앱스토어) | 하나로 두 스토어 | 결제 |
| 광고 | Unity LevelPlay 또는 Google AdMob (중개) | | 광고 |
| 백엔드 | Unity Gaming Services (인증, 클라우드 저장, Cloud Code C#) 또는 PlayFab | 서버 재현에 같은 C# 코드 사용 가능 | 고용·이력·검증 |
| 로그인 | Google Play 게임즈, Game Center, Apple 로그인 | 스토어 정책 | 로그인 |
| 씬 생성 | 에디터 메뉴로 자동 생성 | 클라우드에서 에디터 실행 불가 | 개발 환경 |
| 저장소 | 현재 `my-project-sample`, Git LFS | 큰 에셋 관리 | |

## 2. 확정 시점

- 설계 뼈대를 마무리하고 `design-v1` 태그를 찍은 뒤, 이 문서의 후보를 확정한다.
- 확정 전에 웹 2D로 규칙을 검증하는 경우, 그 구현은 `impl/web/`에 따로 둔다.

## 3. 다른 구현을 추가할 때

```
docs/impl/
├─ unity/      ← 이 구현
├─ web/        (예: 웹 2D 검증용)
└─ <엔진>/     (예: 다른 엔진)
```

- 각 구현은 같은 설계 문서와 같은 데이터 형식을 따른다.
