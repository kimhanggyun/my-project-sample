# 전투 기획서 (와룡전 스타일)

> 상태: 기획 중 (구현 전)
> 범위: **전투 모듈만**. 전략(국가 경영) 화면은 이후 확장으로 붙인다.
> 참고: 「삼국지 와룡전」 전투지휘 영상(안읍 전투, 장비군 vs 하후연군), 와룡전 전투 시스템 분석 자료

---

## 0. 확정된 결정

| 항목 | 결정 |
|---|---|
| 엔진 | Unity, **3D** |
| 플랫폼 | 모바일 (안드로이드 우선) |
| 화면 방향 | **세로** |
| 전투 방식 | 실시간 자동 전투 + 플레이어 지휘, **일시정지 / 배속(1~3배)** |
| 명령 단위 | **군단 단위** (소부대 6개 배치는 진형으로 결정) |
| 첫 구현 전장 | **야전** → 이후 성새전(공성·수성) → 수상전 |
| 데이터 | 전투명·부대명·병력·맵·보상 등 **모든 값은 JSON**. 공통 기본값 + 스텝별 덮어쓰기 |
| 미니맵 | 기본 숨김, 버튼으로 펼침 |
| 스토리 | 임시 텍스트로 채우고, 나중에 파일 교체 |

## 1. 전투 구조

```
전투 (예: 안읍 전투, "유비 대 장로")
 ├─ 아군: 대장 + 군단 N개
 └─ 적군: 대장 + 군단 N개
      └─ 군단 = 장수 1명 + 총병력 + 예비 병력 + 사기 + 진형
           └─ 소부대 6개: 선봉 / 중앙(장수) / 좌익 / 우익 / 좌비 / 우비
                각각 병종(보병·기병·궁병)과 화면 병사 수를 가짐
```

- 플레이어는 직접 싸우지 않고 **군단 선택 → 진형 → 명령**으로 지휘한다.
- 화면에서는 "선택한 아군 군단 vs 선택한 적 군단"의 대치 상황을 보여준다.

## 2. 핵심 시스템

### 2.1 명령 (군단 단위)

| 명령 | 동작 (초안) |
|---|---|
| 돌격 | 공격력 크게 상승, 방어 하락, 빠르게 돌진 |
| 공격 | 일반 교전. 지정한 적 군단 또는 가장 가까운 적 |
| 대형 | 현재 진형을 유지하며 전진/정비 |
| 성벽 | (성새전 전용) 성벽 위 배치·공격 / 성문 공격 |
| 수비 | 제자리 유지, 방어 상승 |
| 후퇴 | 전장 이탈, 병력 보존 |
| 위임 | AI 자동 지휘로 전환 (토글) |

### 2.2 진형
- 6개 소부대의 상대 위치 배치. 전투 중 변경 가능.
- 진형마다 공격·방어·이동속도 보정.
- 첫 버전 4~6종으로 시작, JSON으로 추가.

### 2.3 병종 상성과 방향
- 보병 · 기병 · 궁병 3병과 상성.
- 공격 방향에 따른 피해 배율: 정면 / 측면 / 배후.

### 2.4 예비 병력 보충 (리스폰)
- 군단 최대 병력(기본 6,000)이 전부 화면에 나오지 않는다.
- 소부대마다 **화면 병사 수 상한**이 있고, 병사가 죽으면 예비 병력에서 화면 밖으로부터 걸어 나와 빈자리를 채운다.
- 예비 병력 게이지가 바닥나면 더 이상 보충되지 않는다.
- 3D 모바일 성능 관리 장치를 겸한다.

### 2.5 사기
- 하락 요인: 병력 손실, 측면·배후 기습, 문관(무력 낮은 장수) 피격, 일기토 패배.
- 사기 또는 예비 병력이 기준 이하가 되면 장수가 **성향에 따라 자동 퇴각**.
- 장수는 병력이 0이 되어도 죽지 않고 퇴각 / 부상 / 포로 중 하나의 결과를 가진다.

### 2.6 장수 능력치
| 능력치 | 역할 |
|---|---|
| 무력 | 야전 공격력, 일기토 |
| 통솔 | 성새전 방어력, 전선 유지력 |
| 지력 | 책사 자동 전술(버프) |
| 성향 | 퇴각 기준 |

### 2.7 일기토
- 야전 시작 직전에 조건부 발생하는 이벤트.
- 기본 조건: 두 장수의 무력 차이 3 이내이면 높은 확률. 책사형 장수는 거부.
- 패배 측 군단 사기 대폭락.

### 2.8 책사 자동 전술
- 지력 기반 자동 스킬(아군 버프 등). 장수별로 데이터에서 지정.

## 3. 전장 유형

| 유형 | 특징 | 구현 순서 |
|---|---|---|
| 야전 | 평지 진형 싸움, 무력 중요, 일기토 발생 | **1차** |
| 성새전 | 성벽·성문·해자·다리, 수비 측 성벽 보너스, 통솔 중요 | 2차 |
| 수상전 | 배·배다리 좁은 지형, 대형 유지 어려움 | 3차 |

- 맵은 **조립식 지형 부품**(평지, 숲, 언덕, 강, 다리, 성벽, 성문 …)의 배치로 정의.
- 부품마다 이동속도 / 방어 보너스 / 통과 가능 여부를 데이터로 가진다.
- 전장 유형별 규칙(예: 수상전 진형 흐트러짐)도 맵 데이터 값으로 둔다.

## 5. 확장 구조: 전투 모듈의 입구와 출구

```
[BattleSetup] → 전투 모듈 → [BattleResult]
```

- **BattleSetup (입구)**: 지금은 스텝 JSON에서 생성. 나중에 전략 화면이 같은 형식으로 만들어 넘긴다.
- **BattleResult (출구)**: 승패, 군단별 남은 병력, 장수 상태(퇴각·부상·포로), 공적·경험치.
- 전략 화면을 붙여도 전투 코드는 수정하지 않는다.
- 전투 규칙(Model, 순수 C#)과 표시·입력(View, Unity)을 분리한다.

## 6. 데이터 구성

```
Data/
├─ Master/                 공통 기본값
│   ├─ generals.json       장수: 무력·통솔·지력·성향·자동 전술
│   ├─ troopTypes.json     병종: 상성, 속도
│   ├─ formations.json     진형: 6개 소부대 배치, 보정치
│   ├─ terrain.json        지형 부품
│   └─ balance.json        전투 공식 상수, 퇴각 기준, 일기토 조건, 화면 병사 상한 등
├─ Maps/                   맵별 지형 배치
├─ Steps/                  스텝별 전투 설정 (step01.json …)
└─ Story/                  대사 (임시 → 추후 교체)
```

| 일기토 발생 무력 차이 | 3 이내 |

## 7. 미결 사항

- [ ] 한 전투에서 한쪽당 군단 최대 수
- [ ] 명령 6개의 세부 동작 확정 (특히 "대형", "성벽")
- [ ] 첫 버전 진형 종류
- [ ] 첫 버전 병종 (보병·기병·궁병 외 추가 여부)
- [ ] 승리 조건 종류 (적 대장 격파 / 성 점령 / 시간 버티기)
- [ ] 장수 성장(경험치·레벨업) 규칙
- [ ] 3D 에셋 방향 (로우폴리 임시 에셋 → 교체)

## 8. 구현 단계 (예정)

- **Step 1**: 뼈대 — Boot, 타이틀(임시), 설정, 씬 전환, 데이터 로딩, 세이브, 임시 스토리 출력
- **Step 2**: 야전 전투 — step01.json 기반 전투, 결과(경험치·레벨업) → 저장
